# Triage of the 67 failures of the 10.0.0 release suite, against main at 84d1adbe

Triage of 2026-10-14. Source list: research/PACKAGE_FINDINGS.md, "Release suite of 10.0.0 (2026-10-08): 67 failures".

## Summary

| Class         | Failures          | Meaning                                                                                                                                   |

| STALE TEST    | 55                | The test expects a look, a selector, a count or a colour format from before the character rounds; the code is right, the test must change |

Not one failure turned out to be only "a timeout while the screenshot check ran alongside". Five failures are timeouts (calendar, nostromo progress label, datatable 834, kpi-columns 390, tour is not one), but each time the timeout was a symptom: a stale selector, a block hidden by a verdict, or a button the catalogue now disables.

### How this was done

- Constraint kept: no `test:*`, `verify` or `playwright test` command was run and `.claude/release-go` was not created.
- "Measured" means a standalone node script (in the session scratchpad, not in the repo) opened the page in Firefox on a local static server and ran the same steps as the test body, or measured the one thing it asks. For about half of the groups I ran the spec's own code through a small shim of `test`/`expect`, in Firefox only, one test at a time, to see the failure as it is on main today.
- "Read" means classified from the test and the code without running it.
- The failure list names no theme for most rows. Where the 10.0.0 error is not known, the class describes what the test does on main today.
- `tests/fixtures/.build` (a git-ignored build output) was regenerated by running `tests/global-setup.mjs`; no tracked file changed. The only file written in the repo is this one.
- 10.0.0 still had 19 themes. Since then high-contrast, sepia and retro are gone (600dbcbb) and `themes/order.json` lists 16.

## The groups, in plain English

### auto-lazy (rows 1 to 5)

The test opens every page twice, once as it is and once with the old "attach every module" loader, and compares the markup. A difference means a module is missing from the page's `when` list. All five differences are in the comparison side, not in js/auto.js. The "every module" loader in the test (`EAGER`, tests/auto-lazy.spec.mjs:34) was last extended for progressbar, actions, kpi, attention, tiles, freshness and chart, but not for js/graph.js, js/menu-button.js and `attachKpiStrips()`. With those three added, chart, data and overlays are identical (measured). Feedback differs only in the timestamp attributes of the "updated 48 s ago" labels. The catalogue index (row 5) composes itself in two steps, at about 1 s and at about 5 s (20 450 then 25 463 elements, measured); the test's two-readings-agree rule takes the first plateau, so it is timing. A user would see nothing wrong. Measured.

### cyberpunk charge sweep (row 6)

The test hovers every button and wants the `kp-charge` sweep in a colour 3:1 from the face. On main the button's `::after` is the notched focus/hover ring with `animation: none`; the hover rule at css/cyberpunk-register.css:1543 and `@keyframes kp-charge` (line 1663) lose to line 2440 and are dead code. The look was changed on purpose in the cyberpunk round and approved. A user sees the ring, no sweep. Measured (animation name `none` on all six variants).

### Focus rings (rows 7, 14, 15, 16, 18, 23)

Four different tests ask "does a focus ring show" in four ways: declared outline plus two shadow layers (button.spec, dashboard 255/322), pixels in the `--focus-ring` colour (dashboard 291), an inward outline or inset shadow (datatable-more), and a screenshot difference per edge (focus-visible). The first three were written for one ring grammar. The character rounds (3eba5336, 0b5434db) gave each theme its own focus mark. The screenshot test, the one that does not care how a ring is built, passes in 13 of 16 themes; cyberpunk and terminal fail on band geometry (cyberpunk's ring is a visible inset line, seen in a screenshot), and phantom fails to settle its animations (new, not in the 10.0.0 list; see F-b). Measured in Firefox. Seven themes fail the declared-style test; the pixel test shows rings in all of them. What would need Kenny: nothing, but the four tests should be replaced by one theme-agnostic pixel measure.

### Calendar (row 8) - real

The test paints September, August and July in each of 16 themes, wide and in the 334 px phone pane, and wants the nav on one line, six rows, one height, and today's ring at 3:1. Measured on main: in formal's phone pane in September the title is 155 px wide and the fourth nav button ends 7 px past the right edge of the calendar card (the small buttons are 53, 54 and 55 px). A user sees the last nav button hanging out of the card. The cyberpunk (1.20:1) and terminal (2.92:1) ring lines are the test reading the first `box-shadow` colour of a today cell those themes draw another way (stale). Measured.

### Catalogue review (rows 9 to 12)

These test the catalogue's own review dialog, not the package. Row 9 passes now. Row 10 expected the old end-of-theme sentence. Row 11 (two tests) concerns where the review note sits after the review rework; I read, not measured. Row 12 visits the archived grotesk-hover demo, which no longer carries the prompt bar. A package user sees none of this.

### Titanium and dark "a click is seen" (row 13)
