# Data table features: what to build, what to lose, which defaults

Kenny, 2026-09-13: the data table should search in specific columns and
offer filters; build a demo page to decide which features to implement or
lose, and which defaults to use. Also: the footer needs room between the
table edge and the row count, and under it.

Demo: [`demo.html`](demo.html), in the catalogue under "Research demos →
Data tables". One block per feature, one dataset of 60 incidents. Blocks
tagged **package today** are `.kp-datatable` driven by `js/datatable.js`;
**mock** blocks are page-only script and `dtr-` styles on package classes.

## Measured faults in the current table

Firefox (Playwright 1538), `catalogue/table.html` and this demo, 1280 px and 400 px.

1. **Footer against the edge.** Status text 0 px (cyberpunk), 1 px (formal, nostromo, light), 3 px (brutalism) from the frame's left edge; pager 1–2 px above the bottom. `.kp-datatable` has no padding; the registers give it a border. With `kp-px-md kp-py-sm` on the bars: 12–13 px and 9–10 px.
2. **Select-all goes past the page.** On `table.html` one click ticks 24 rows while 8 are on the page; on the demo 60 while 10 are. The label says "Select every visible row". React's `visibleKeys` selects only the page, so the two channels disagree.
3. **Stale header checkbox.** Tick a row, then search it out of view: the header box stays `indeterminate` over 3 unticked rows. `applyFilter` never calls `syncSelectAll`.
4. **No per-column order.** Severity sorts Critical, High, Low, Medium. The framework-free channel only has a global `compare` option.
5. **React sort header.** `.kp-datatable__sort` is `display: block` inside a `th` whose `::after` draws the arrow, so the arrow drops to a second line. Injected in formal: th 48.5 px, button 32 px; the same markup on this demo in nostromo gave 65 px against 32 px. The button also resets `text-transform` and `letter-spacing`, so nostromo's uppercase headers lose their case. It pads with `--kp-table-cell-pad`, a knob grep finds nowhere else.
6. **Compact misses the search box.** Row 38.7→30.7 px (formal), 42.6→34.6 (nostromo), 38.5→30.5 (cyberpunk). Pager buttons shrink too. The search box stays 38 / 44 / 39 px.
7. **Badges break mid-word** in nostromo at 1280 px ("WATCHI / NG"), from the default `--kp-badge-wrap: anywhere`.
8. **Cards cannot sort.** In card form the headers are visually hidden, and they are the only sort control.
9. From the code, not a browser: a bare sortable `th` gets `tabindex="0"` with no button role. After a sort, every other sortable header gets `aria-sort="none"`, where the APG example keeps `aria-sort` on one header.

Not the data table, but seen while measuring: `catalogue/table.html` in brutalism at 400 px scrolls sideways by 166 px. The overflowing elements are in its `#empty` block.

## Recommendation

**Build now:** filters, and search that can be limited to one column. That
is what Kenny asked for, and the rest of the table depends on them. Declare
both per column in markup (e.g. `data-kp-filter="choice|range|date"` on the
`th`), so a server-rendered table still works for kyu and Almanac. Fix
faults 1–8 in the same release. Ship the defaults from the last demo block:
25 rows, sticky header when a height is set, footer inset, badges whole.

**Later:** multi-sort, column visibility, row expansion, fixed column,
framework-free server mode. Each is real, but none was asked for and each
needs its own state in the handle.

**Leave out:** export, inline edit, keyboard grid. TH42 already calls these
a grid, a different product. The APG grid pattern says a read-only table
should stay a table. Export is a few lines for an app once the handle
returns the view's rows, so offer that instead.
