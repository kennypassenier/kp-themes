The alarm: a full-screen dramatic alert

Kenny asked for something bigger than a toast: a full-screen overlay with animated red text, "ACCESS DENIED" as a film would show a hacking attempt, with the words set by the caller, and a choice between having to click something and going away by itself after a number of seconds. This page is a working prototype of kp-alarm. Parts marked package are the stylesheets and scripts as they ship (the tokens, the registers, .kp-button, .kp-field, .kp-fieldset, .kp-sr-only, the native <dialog> the package's dialogs already use, and the decipher glyph set from js/effects.js). Parts marked mock are written on this page: every kp-alarm rule, its keyframes, and the showAlarm() function. Loaded registers: cyberpunk, nostromo, terminal, synthwave, formal, light. The page opens in cyberpunk.

mock Theme:

Try it mock

Look at: press Raise the alarm in each theme. In the four sci-fi themes the screen goes dark red, the headline flickers in, each letter decodes through two noise glyphs into the words you typed, and a split copy slices through it once; the frame breathes slowly, the hazard bars march, a faint band sweeps down. In formal and light the same call gives the restrained version: a plain panel with two thick red rules and no flicker. With Must be acknowledged, only the button (click, Enter or Space) closes it; Escape does nothing unless you tick it, and clicking outside the text never closes it. With Closes by itself, the bar empties over the seconds you set, Keep open turns it into the acknowledged kind, and Escape closes it. After it closes, focus must be back on the button you pressed. Set Motion to still to see what a reader with reduced motion gets. The controls and the trigger are package classes; the alarm itself is the mock.

The API sketch: script, markup, React mock

                

                    Look at: whether the option names read naturally. The script version on this page is real and runs the trigger above; the
                    markup is what it builds; the React component is a sketch only, not built or tested. All three share one vocabulary:
                    title, detail, code, mode (ack or auto),
                    seconds, escape, action, drama, motion. The promise resolves with
                    why it closed: ack, timeout or escape.
                

                
// js/alarm.js (proposed): framework-free
import { showAlarm } from '@kp-soft/themes/js/alarm.js';

const reason = await showAlarm({
    title: 'Access denied',
    detail: 'Three failed attempts on terminal 4. This console is locked for ten minutes.',
    code: 'Security protocol 7 · lockout',
    mode: 'ack',          // 'ack': a button must be pressed · 'auto': closes after `seconds`
    seconds: 8,           // auto only
    escape: false,        // ack only: may Escape close it too
    action: 'Acknowledge',
    drama: 'theme',       // 'theme' reads --kp-alarm-drama · 'full' · 'restrained'
    motion: 'system',     // 'system' follows prefers-reduced-motion · 'still'
});                       // resolves 'ack' | 'timeout' | 'escape'

// components/Alarm.jsx (sketch, not built): the same options as props
export function Alarm({ open, title, detail, code, mode = 'ack', seconds = 8,
                        escape = false, action = 'Acknowledge', drama = 'theme', onClose }) {
    const ref = useRef(null);
    useEffect(() => {
        const dialog = ref.current;
        if (!open || !dialog) return;
        dialog.showModal();                       // top layer, page inert, focus trapped
        const onCancel = (e) => { if (mode === 'ack' && !escape) e.preventDefault(); else onClose('escape'); };
        dialog.addEventListener('cancel', onCancel);
        const timer = mode === 'auto' ? setTimeout(() => onClose('timeout'), seconds * 1000) : 0;
        return () => { clearTimeout(timer); dialog.removeEventListener('cancel', onCancel); dialog.close(); };
    }, [open, mode, seconds, escape]);
    const id = useId();
    return (
        <dialog ref={ref} className="kp-alarm" role="alertdialog" aria-labelledby={`${id}-t`}
                aria-describedby={`${id}-d`} data-kp-alarm-mode={mode} data-kp-alarm-drama={useDrama(drama)}>
            <div className="kp-alarm__panel">
                {code && <p className="kp-alarm__code">{code}</p>}
                <h2 className="kp-alarm__title" id={`${id}-t`}><Decipher text={title} /></h2>
                <p className="kp-alarm__detail" id={`${id}-d`}>{detail}</p>
                {mode === 'ack'
                    ? <button className="kp-button kp-button--destructive kp-alarm__ack" autoFocus
                              onClick={() => onClose('ack')}>{action}</button>
                    : <Countdown seconds={seconds} />}
            </div>
        </dialog>
    );
}

            


            
            

                
The flash budget, as designed mock

                

                    Look at: every animation the full drama runs, with how often it changes brightness. WCAG 2.3.1 allows at most three flashes
                    in any one second, a flash being a pair of opposing brightness changes of 10% or more; red flashes are judged more strictly. The
                    worst second is the first: the headline flickers in with three changes (0, 1, 0.3, 1), which is one and a half flashes. After that
                    the whole alarm stays under one flash per second. The measured result from the Playwright run is in the README.
