# Futuristic interface layouts — FUI research

Researched 2026-09-13 for kp-themes. FUI ("fantasy" or "fictional user
interfaces") is the film and television craft of screens that must read
in a second from across a set. This note extracts what actually defines
each look — the page shape, not the colour — and proposes six layout
concepts the package could adopt as page shapes a theme then paints.
Nothing here was downloaded or copied; every reference is described and
linked. Sound is out of scope. The mockups are in `demo.html` beside this
file.

### What actually defines the look, across the references

- **Page shape.** A frame that is not a rectangle: the LCARS elbow and
  rail; the HUD's corner brackets and peripheral gauges; Westworld's three
  panes; the dispatch console's fixed regions. In every case the frame is
  _asymmetric_ and _static_, and the content inside it is plain.
- **Typography.** Condensed uppercase sans for structure (LCARS, Expanse),
  monospace for readouts and logs (Iron Man, Nostromo, the wiretap room),
  and one deliberate oddity per world (a stretched serif on MU/TH/UR,
  multi-script signage in 2049). Tabular figures everywhere a number
  updates.
- **Grid and density.** Two extremes: the sparse ceremonial screen
  (Westworld, Wallace) and the dense operational board (CAD, Roci,
  Agatha King). Density is a register, not an accident; the Expanse's
  command line next to the GUI is how a screen says "functional".
- **Colour logic.** Colour means _role_, not decoration: warm structure
  vs cool data (LCARS); faction (Expanse); class (2049); alert vs readout
  (Iron Man). One red for the thing that matters. This is exactly the
  package's token model — role tokens, a theme paints them.
- **Chrome.** Hairline rules, corner brackets, a status strip at an
  edge, pill-capped bars, bezels and screen burn as _wear_. Scanlines
  and vignette are already in the cyberpunk and terminal registers.
- **Motion.** The good references move little: a ticker, a countdown, a
  scanning line, a bracket that snaps to a target once. The bad ones
  (Minority Report, the HUD's parallax) move everything. The package's
  DI5 and reduced-motion rules already draw that line.

## 2 · Layout concepts

Not colour themes: page shapes a theme could adopt. "Reuse" names what
exists today (`docs/LAYOUT.md`, `css/components.css`, the hook vocabulary
in `js/effects.js`); "New" is what would have to be added. Every new
paint is a token, never a literal (DI9); every new token lands on all
twenty-five themes in the same change (S47).

## 3 · Recommendation: build D and B first

**D, the HUD bracket, first** — it is the cheapest, and it is the only
concept that fits the package's grammar without a new layout: a _hook_
every theme answers (S45), like `data-kp-divider`. Cyberpunk already
draws the corners on its `h2` with four gradients; that technique
generalises to any box in a day. Nostromo would answer with label-tape
corners, terminal with `+` glyphs, formal by not answering — which is
allowed. It gives every theme a "look here" device for media, heroes and
selection without a token, so S47 costs nothing.

**B, the dispatch console, second** — it is the shape Kenny's own pages
have (a queue, its states, its history) and it reuses the most: the
marquee, the table, the badge, the health dot and the timestamp are all
there; what is missing is the grid that holds them and the priority plate.
It is a layout class, so it is theme-independent, and the one motion it
adds (a changed row lighting once) is a single TIMINGS row.

**Why not A first.** The elbow frame is the most recognisable shape in the
list, and the CSS is small — but it needs a structural colour trio on all
twenty-five themes (S47), it only makes sense as a full-bleed shell (it
fights `.kp-page`'s centred measure), and it is one show's silhouette
rather than a grammar. It is the right _second wave_, once D has shown
that a shape can be a hook and B has shown what a full-page layout class
costs. C is a demo-only shape until someone has a page that needs
strings; E and F are small enough to ride along with whichever page asks
for them first.
