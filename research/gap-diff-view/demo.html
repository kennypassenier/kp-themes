A diff of several files

The admin dashboard draws the changes of an edit plan itself because the package only had the lines of one diff. This is the diff for several files: a header per file with its status and exact counts, unchanged lines folded into one row that opens in place, the changed words marked inside a changed line, and reading, empty and failed states. Everything here is mock data in the shape of the dashboard’s plan (the jellyfin, sonarr and traefik stacks); formal only, the other themes come after you approve it.

Several files in one diff

The edit plan of the media stack as the dashboard shows it before it is applied: one block per file, each with what happened to the file, its path and how many lines changed.

Expected:

  • Every file has a header: a status word on a badge (Modified, Renamed, Added, Removed, Binary), the path with the folder quiet and the file name strong, and exact +N and -M counts. The counts and the five little blocks stand in the same column in every header.
  • A renamed file shows old path → new path; a renamed file with no line changes says No line changes in this file. and a picture says Binary file, not shown.
  • A header opens and closes its file (Enter or Space on the header); Expand all and Collapse all above do every file, and each is off, with its reason on hover, when it has nothing left to do.
  • Open decides which files start open; Header blocks and Copy path show or hide those parts of every header; each press changes the diff at once.

Formal is the ruled ledger: an opaque paper plate in a strong hairline, flat and ruled, nothing fades. Check that each file block reads as one ruled entry, that the counts line up from header to header, that every label is whole and clear of its plate’s edge, and that at 390 px the path takes its own line under the status.

Unchanged lines fold away

A long run of lines nobody touched becomes one row, “42 unchanged lines”, that opens where it stands, so the change is what you see.

Expected:

  • In the static config three runs fold with the default of 3 kept lines: the start of the file, the stretch between the two changes and the end. Each fold row says its exact number and is a button; Enter or a click opens it in place, and the same row now says Hide 42 unchanged lines.
  • Context lines: with 1 more is hidden, with All shown nothing folds. A run that would hide fewer than 3 lines is never folded.
  • A new file has no unchanged lines, so nothing folds and every line is shown with a plus sign.
  • Opening a fold keeps the focus on its row, and the line numbers stay true: the new file’s number for kept and added lines, the old one for removed lines.

Formal: the fold row is a quiet dashed rule across the three columns of the diff, its words standing where the code stands. Check that the words are clear of the edge, that the three dots turn into a single rule when the fold is open, and that opening a fold moves nothing above it.

The changed words inside a line

When a line is replaced by a nearly identical one, only the words that differ are marked, so a version bump reads as the version and not as a whole line.

Expected:

  • Image tags: in jellyfin/jellyfin:10.11.11 becoming jellyfin/jellyfin:12.1.0 only the version is marked. Added words are bold and underlined, removed words bold and struck through, so the two sides differ without colour.
  • Settings marks the port, the log level and the memory limit alone; Log lines marks the dates, the times and the version in a startup log, and a line that has no partner stays plain.
  • A rewritten line is not marked word by word: when more than 60% of a line changed, the whole line is the change and marking every word would say nothing.
  • Words: Not marked shows the same lines with whole-line tints only.

Formal: a deeper tint and a heavier weight inside the line, nothing flashing. Check that the marked words stay inside their line without moving the text beside them, that the sign column and the numbers stay quiet, and that a marked word is readable on both the green and the red line.

Reading, nothing changed, could not read

The three states a diff has besides the changes themselves, each in the box the diff had so nothing around it jumps.

Expected:

  • Reading shows the file headers at their final size with the theme’s busy card in the middle, and it keeps animating.
  • Nothing changed is the package’s empty plate at heading size, centred, with the names that were compared; Could not read is its alert with the reason and a normal-size Try again.
  • Each state has the height the changes had (measure it by pressing Changes shown and then a state): the surroundings do not move. Try again reads again and shows the changes.

Formal: the empty plate is dashed and muted, the failed plate is the red alert; both are centred in the whole box with air on every side. Check the box keeps the same height in all four states and that Try again is a normal button, not a strip.

A long file draws a first part

A file added whole, with 453 lines, draws its first lines and keeps the rest behind one button, so the page stays quick and nothing is lost.

Expected:

  • With 40 lines first the file shows 40 lines and a row Show the other 413 lines; with 400 (the default) it shows 400 and Show the other 53 lines; with All there is no row.
  • Pressing the row draws every line of that file at once and says so politely to a screen reader; the count in the header (+453) never changes.
  • A file added whole has no unchanged lines, so no fold rows appear in it.

Formal: the “show the rest” row looks like the fold row, a quiet dashed rule across the diff’s columns with its words where the code stands. Check that the exact number is on the row, that it is clear of the edge, and that the lines drawn do not shift when the row is pressed.
