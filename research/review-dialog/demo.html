The review dialog: one block at a time, by keyboard

Kenny asked on 2026-09-15 [scope-89] for a large dialog of fixed size that opens one block, puts the cursor in the note so he can type at once, moves between blocks with Left and Right, approves with Up and rejects with Down — a rejection only with a note — and moves on by itself after each verdict. This page builds that dialog over eight real catalogue blocks. What is mock: the dialog, its keys, the arrow switch and the prompt preview below (every rd- class). What is real: the eight blocks, read at load from their component pages exactly as catalogue/review.js reads them, the package's .kp-dialog, .kp-button, .kp-field and .kp-badge, and the block hash from catalogue/block-hash.js. Verdicts and notes made in the dialog stay on this page: nothing is written to the register or to this browser's storage.

Try it mock

Look at: press Review in a dialog in the top bar, or Open in the dialog beside any block below. The cursor must be in the note field at once, on every block you reach. Press Down with the field empty: nothing is rejected and the reason is shown under the field. Type a few words and press Down again: the block is rejected and the next one opens by itself. Up approves the same way. Then try each arrow setting below while a note is half written, and decide which one you want: the setting only changes what Left and Right do. Escape closes the dialog and brings you back to the block you were on; Tab never leaves the dialog. Switch the theme in the bar and open it again: the dialog is drawn by the theme's own .kp-dialog.

Down not approved, only with text in the note; then the next block not yet judged
Escape / Tab close and return to the block on the page / cycle inside the dialog only

The keys only act while focus is in the note or on the dialog's own buttons. Inside the block under review — a date picker's grid, a data table's cells, a tab row — the arrows stay the component's own.
