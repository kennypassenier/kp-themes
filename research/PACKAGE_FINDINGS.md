## Formal

- **js/motion.js cannot replay an animation of a custom property (found 2026-10-08, applying formal).** `Element.getKeyframes()` leaves custom properties out, and `rememberEntrance()`, `entranceOf()` and `arriveAsReversedLeave()` replay what it returns with `target.animate(keyframes, ...)`, so a dialog, a drawer, a tour card or an arriving element whose register animates a `--x` plays nothing, opens and closes with an empty animation, and the leave of one that is not turned round by CSS is a pause. Formal therefore rules those with ordinary keyframes (clip-path, one pair per line, the wait carried in the offsets) and keeps the custom-property animation for what `playEntranceBackwards()` turns round in CSS (a menu, a popover, a tooltip, a combobox list, a date panel). What it would take: motion.js reading the registered custom properties of a keyframe from the animation's computed style (a `getComputedStyle` sample at 0 and 1) or taking the keyframes from the stylesheet rule.
- **A leave and an arrival are played element by element, not line by line (found 2026-10-08).** `arriveAsReversedLeave()` and `leaveOne()` read the animations whose target is the element and its pseudo-elements; a dialog's subtree is read (`entranceOf()`), an arriving card's is not. Formal's grammar rules what arrives frame first, then its lines top down; for a card, an alert, a key figure it can only rule the frame and the pen of its top edge. What it would take: the same `subtree: true` read in the arrival and the leave, each target kept with its own wait (the waits of a dialog's entrance are dropped too: `closeDialog()` and `openAsReversedClose()` animate every kept entrance with one duration and no delay, which is why formal's offsets live in the keyframes).
- **The live update's time cannot be set by a register (found 2026-10-08).** `--kp-update-duration` is 1.25 times the larger of the size and the close time (js/update.js, `updateTimingOf()`), so formal's ruled-and-closed update lasts 850 ms (a rule 400, the second 160, the lift 240) because its dialog does; a register that knows its own update time cannot say it. A `--kp-update-time` it could set on the root would do.
- **A register cannot say how many lines a panel has (found 2026-10-08).** The ruled opening of a menu or a popover needs the number of its entries to give it no dead time at its end; formal counts them with `:has(> :nth-child(k))` up to eight, and a menu of more than eight rules its ninth and later entries with the eighth. A `--kp-menu-count` set by js/menu-button.js (the same for the popover with a menu in it) would remove the cap.
- **The manners (hover, focus, press) cover what the register names, not every control (applying formal, 2026-10-08).** The selector list is `.kp-button`, `.kp-icon-button`, `.kp-menu__item`, `a.kp-kpi`, `.kp-kpi--toggle`, `.kp-calendar__day`, `.kp-kpi__link`, `.kp-nav__link` and the text links; tabs, pagination, accordion summaries, tree rows, the sidenav, the chart's legend keys and the combobox options keep the package's own answer to the pointer. A grammar question for Kenny, not a missing hook.
- **Research variants whose description text is shared by every theme (applying formal, 2026-10-08).** research/character-chart/demo.js builds the loading and arrival texts from one `KIND` table for all themes, so formal's two redrawn options carry a theme condition there (as light's already do); a table per theme would remove the conditions.
