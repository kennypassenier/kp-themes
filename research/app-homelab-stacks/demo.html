Homelab dashboard: stacks, apps, changes and the Map on kp-themes 11.0.0

The dashboard of the host pve has a Stacks page (the fleet, the Apps launcher, Presets, Retired), a page per stack with the Apply and Update flows, and a Map. This page rebuilds their parts from the package’s own components, in formal. Each of the 23 sections asks one thing to look at; where a choice exists, its options are real and switchable and you only say which one opens first. Nothing is required.

Mock on this page: every stack, app, size and date is sample data in the dashboard’s own shapes (jellyfin, immich, paperless, vaultwarden, traefik, prometheus, grafana, loki, kyu, almanac, syncthing, inbox, metrics, admin; the time is fixed at 19/10/2026 09:41). Backend work still needed is said in the section: per-app watch history, a server read of release notes. Left out because the package is still building them: the CPU line on a card, the link tile with a star, and a count on a tab. The Map’s network drawing is not part of this page. Nothing moves until you press a button.

The fleet as cards that keep one height

Shows every stack as one card with its state in words, its figures, its flags, its memory and its buttons; a card is the same height whatever it holds.

Expected:

  • Seventeen cards in a grid of equal columns (.kp-entity-grid). Each shows the stack name with its container number, the state in words (running, needs attention, parked), the figures Apps up, Restarts and CPU, flags (update available, restart loop, parked) and a RAM meter with its 80 % mark. Every card is the same height, with or without flags.
  • The buttons are Deploy and Back up now; on a parked stack Deploy is off and says why (“Parked since 02/09/2026: unpark it first”). Press one and the line under the cards says what would be sent.
  • Show narrows the grid (all 17, the 2 that need attention, the 3 parked) without the cards changing size. Data: Loading lays the busy card over skeleton cards, Empty and Failed fill the same footprint with a plate and a normal-size button.
  • The 24-hour CPU line on each card waits for the package (the card has no sparkline slot yet), so CPU is a figure today. This section is on sample data; it only reads the fleet.

White cards with a hairline, a navy primary and a coloured mark beside each state word (never colour alone). Look at the gap between each figure and its label, that the flags never touch the card edge, that the RAM meter shows its 80 % tick, and that a card with no flag is exactly as high as one with three.
