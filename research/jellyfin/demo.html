Theming the Jellyfin web client with kp-themes

Research demo for research/jellyfin/README.md. Measured against jellyfin-web v10.10.7, v10.11.11 and v12.1, and tested live on a throwaway Jellyfin 12.1 container (loopback only, no library). The container was stopped and removed afterwards.

Theme: mock switcher

1. The verdict package

Look at: whether the four measured numbers are enough to decide, and whether the warning names the right limits. Every card and the alert are package classes (kp-autogrid, kp-card, kp-alert--warning) with no page styling.

Doable on Jellyfin 12.x at medium cost. Custom CSS never reaches the admin dashboard, Android TV or Swiftfin, and Jellyfin 10.11 has no variable layer to build on.

A · Built-in theme ids

One file, keyed on html[data-theme="light"], "dark" and so on. The user picks a theme in Settings > Display and it repaints without a reload. No server files. At most six themes, and they appear under Jellyfin's names ("Light" wears formal).

B · Extra ids via config.json

Add {"id": "kp-nostromo"} to web/config.json and a themes/kp-nostromo/theme.css. Tested live: the new entry was listed, and MUI fell back to its default palette. No limit on themes, but it edits server files, so it needs a volume mount to survive an image upgrade.

C · One file per theme

@import one theme in the server field, or in the per-user field with the server CSS disabled. Simple, but the per-user choice is saved per browser, and switching means editing CSS.
