# Theming the Jellyfin web client with kp-themes

Kenny, 2026-09-17 ("Eerst onderzoek"): can the package theme Jellyfin's web
client, and how brittle would that be? Demo: [`demo.html`](demo.html).

**Short answer:** yes on Jellyfin 12.x, at medium cost. Brittleness depends
on the hook. Jellyfin 12 exposes MUI palette variables, and a theme built on
them held up in a live 12.1 test. Jellyfin's internal class names are a short
list that still changes a little with each major version. Custom CSS reaches
only clients that run jellyfin-web. It never reaches the admin dashboard, and
it never reaches Android TV or Swiftfin.

Measured against jellyfin-web source tarballs `v10.10.7`, `v10.11.11` and
`v12.1` (latest, 2026-09-15). The live test ran a throwaway `jellyfin/jellyfin:latest`
(12.1) container on `127.0.0.1:38096`, with no library and loopback only.
It was stopped and removed afterwards (`docker rm`; the pulled image is still on disk).

**Selector churn, measured** (class names in `src/**/*.scss|css` selectors; "gone" means the name is absent from all of `src`):
10.10.7 → 10.11.11: 3 removed (2 gone), 5 added. 10.11.11 → 12.1: 17 removed (9 gone), 9 added. The built-in dark theme's own selectors: 0 removed → 11 removed. The class names were not the big break in 12.0. The default layout was: [PR #7393](https://github.com/jellyfin/jellyfin-web/pull/7393) made the MUI "modern" app the default (`getDefaultLayout()` returns `'modern'` in 12.1 and `'desktop'` in 10.11.11). That is why ElegantFin tells v12 users to switch back to legacy mode.

**Live prototype (12.1).** `kp-jellyfin.css` is 13,682 B, generated from `formal` and `cyberpunk` tokens with fonts loaded from the pinned jsDelivr tag. Results:

- Legacy layout: fully themed, including the settings list, search field, drawer (opened), action sheet (opened) and the display fonts.
- Modern layout: palette, headings and account menu (opened) followed the theme. The MUI app bar title, the menu items and the selects kept Noto Sans, because Emotion writes a literal font stack there and not the `--jf-font-*` variables.
- Dashboard: unthemed, as the source says.

## Recommendation

Build a small generator, not a port. The steps:

1. Add `gates/generate-jellyfin-css.mjs`. It writes one file from `tokens.json` in two layers: the `--jf-*` values (with channels computed at build time), then about 20 legacy/`Mui*` selectors for the register touches.
2. Key the themes on Jellyfin's built-in ids so a user can switch at runtime without server files. Up to six themes; which kp theme gets which id is Kenny's call.
3. Ship it at a release tag and install it with one pinned `@import` from jsDelivr.
4. Support Jellyfin ≥ 12.0 only. 10.11 has no variable layer, so every colour there would need a selector.
5. Keep the selector list short enough to re-check by diff on each Jellyfin release.

Do not promise the full register look (notches, reveals, textures) on the modern app. It uses generated Emotion classes, so only the palette and some `Mui*` class names are reachable. Do not promise the dashboard, Android TV or Swiftfin. Cost: medium, mostly in keeping the selector list honest across Jellyfin releases.
