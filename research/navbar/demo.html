Navigation alternatives

A research demo for kp-themes. The current .kp-nav comes first, then one section per alternative. Badges say what is the package (package) and what is written for this page only (mock). Every alternative shows its opened state, either live or as a pinned copy. Registers loaded: dark, terminal, formal. js/auto.js sets data-kp-effects on the root itself (attachEffects, js/effects.js line 528), so the registers' reveals run as they would on a consumer's page; the chrome is what you are judging.

1. Mega menu bar: package · panel: mock

One top-level item opens a full-width panel with grouped second-level links. The bar, brand and link list are .kp-nav unchanged; the trigger is a <button aria-expanded aria-controls> (the APG disclosure-navigation pattern, not role="menu") and the panel is a three-column grid on the --popover tokens. Opens on click, closes on Escape (focus returns to the button), on a click outside, and when another trigger opens.

Look at: click Products, then Tab through the panel — every link is reachable and Escape returns you to the button. Open Solutions and see Products close. Hover does nothing on purpose. Frame B pins the panel open in flow. Judge whether the register's dropdown styling (.kp-nav__menu) should extend to a panel this wide — KT14 says a register answers the parts that only show on interaction.

2. Collapsible sidebar / rail package frame + glyphs: mock

.kp-sidenav as shipped, in side mode with data-kp-sidenav-slim and data-kp-sidenav-accordion; attachSidenavs wires the categories. The package has no declared attribute for a slim toggle — the button below calls sidenavOf(nav).setSlim() from js/sidenav.js, which is what a consumer would have to do today. The letter glyphs stand in for icons, because the package ships type and not icons.

Look at: press Collapse to rail — labels go, glyphs stay, the width drops to 4.5rem. Frame B starts as a rail with expand-on-hover: hover it and the labels return without changing the state. Open the Reports category with the keyboard (Enter on the toggle; aria-expanded flips). Then Tab through the collapsed rail with a screen reader in mind: the label is display:none, so a rail link with only a glyph has no accessible name unless the consumer adds one. That is the one accessibility gap this page found.

.kp-palette as shipped: a <dialog data-kp-palette data-kp-hotkey="k"> that attachPalettes wires, a combobox over a listbox, grouped options with data-kp-keys. What is mock: the trigger in the bar (a ghost button with the key hint) and the twelve-line handler that turns kp-palette-run into a hash navigation — the package deliberately leaves the action to the consumer.

Look at: press Ctrl+K (or ⌘+K) anywhere on the page, or click the Search button in the bar. Type age and see Receivables ageing alone survive with the status line counting; arrow down and Enter, and the status under the bar shows where it went. 4. Tab bar as section navigation A: package · B: mock rules

A flat row of peer sections under the title, the way GOV.UK's service navigation does it: links, not tabs, because each one loads a page. Frame A needs nothing new — it is a second .kp-nav with its own aria-label. Frame B borrows the .kp-tabs__list underline look for links, which the package does not style (its .kp-tab rule targets aria-selected buttons); those six rules are the mock.

Look at: the current section is marked by weight and a rule as well as colour (DI4) in both frames. Frame C is 30rem wide: the row wraps rather than clipping. Check that the register treats a second .kp-nav as a quieter row and not as a second brand bar — that is the question this pattern puts to each register.

5. Sticky / shrinking header bar: package · sticky + shrink: mock

The .kp-nav-wrap that already exists gets position: sticky; a scroll listener sets data-demo-compact on the wrap once the frame has scrolled more than 8px, which lowers the package's own --kp-nav-pad-block knob. The transition sits under prefers-reduced-motion; scroll-padding-top keeps anchor targets from landing under the bar.

Look at: scroll inside frame A — the bar stays, shrinks and gains a shadow; scroll back to the top and it grows again. Click the Jump to VAT link: the heading lands below the bar, not under it. Open the Reports dropdown while the bar is compact — it still opens below the bar. Frame B is the compact state pinned, for the registers.

6. Bottom navigation on narrow screens top bar: package · bottom bar: mock

Three to five top-level destinations within thumb reach, per Material 3 and the Apple HIG. The phone frame keeps a plain .kp-nav as the brand bar at the top; the bottom bar is a <nav> of links with aria-current, plus a More disclosure for the destinations that did not fit. The content pads its bottom so the bar never covers the last line. In the package this would be a choice per page against the hamburger collapse the bar already does at 40rem, not an addition to it.

Look at: the current destination is marked by colour and weight; each target is at least 44px tall. Tap or press Enter on More — a sheet rises from the bar; Escape closes it and returns focus. Frame B pins the sheet open. Scroll the content: the last paragraph clears the bar.

7. Breadcrumb + rail package frame + glyphs: mock

Nothing new: .kp-breadcrumb says where in the hierarchy the page is, the .kp-sidenav rail says which area. The breadcrumb sits before the content, where a skip link would skip it, as GOV.UK places it. The separator is the package's --kp-glyph-breadcrumb knob, which a register may change.

Look at: the rail is collapsed in frame A and the trail carries the hierarchy: Invoices › Acme Wholesale › INV-2041, last item aria-current="page". Hover the rail: it expands on hover without changing state. Frame B is the same shell with the rail expanded. Judge whether two navigations on one screen read as one system in each register.

8. Two sibling questions tabs: package · segmented control: mock

Tabs vs. segmented control. Tabs are attached to panels on the same page (role="tab", one tabpanel each; the package's attachTabs gives the arrow keys). A segmented control is a single-choice setting that changes how the same content renders — list or grid, day or week — and is honestly a radio group; the mock below is fieldset + three radios, which the package does not ship. Sidebar vs. rail is sections 2 and 7: in this package they are one component in two states, .kp-sidenav with and without data-kp-sidenav-slim-collapsed.

Look at: in the tabs, arrow keys move between tabs and the panel follows (automatic activation). In the segmented control, arrow keys move the choice the way a radio group does, and the focus ring is the theme's --focus-ring. Both should read as one family in each register; the segmented control's selected plate uses --primary, which is where a register would want a say.
