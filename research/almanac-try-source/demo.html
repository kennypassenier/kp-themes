Almanac: try a source before it writes

Two new Almanac pages in one demo: Try a source (paste an event call, see exactly what Almanac would put in the calendar, nothing is written) and the source profile view. The page is built from kp-themes 11.0.0 parts only, in formal. It never calls a server: the answers come from a small port of Almanac’s own dry-run rules (engine.js), checked against the two pinned fixtures byte for byte. Sample data: only home-assistant is a real profile name; the other three sources, every calendar id and the event already in the calendar are made up. Today is 19/10/2026.

Pick a source and read its profile

Every source has one small profile file that says which calendar its events land on, in which time zone, and how long an event lasts when the call does not say; the summary and the file are shown together.

Expected:

  • Four sources in a segmented control. Pressing one changes the title, the badge, the facts and the file at once; the file is copied with its Copy button and wraps with Wrap.
  • The facts stand in one grid (calendar, calendar id, time zone, default length, schema version, file); the three choices in the dialog change their layout live. Sample data: three of the four source names and all calendar ids are made up.
  • Loading shows the busy card over the whole card, Empty and Failed fill the card’s footprint with a normal button (Reload profiles, Try again).

Press each source: facts and file change together and nothing jumps. Put the card in Loading, Empty and Failed: each fills the whole card, as high as the filled one, with a normal-size button.

Write the event call and check it before you send it

Paste or edit the JSON a source would send. The field marks the line that is wrong and refuses a call Almanac would refuse (an unknown field, a missing title); Try asks Almanac what it would put in the calendar and writes nothing.

Expected:

  • Home Assistant sample and Everything sample are the real payloads from fixtures/payloads: valid, Try is enabled and answers Accepted. Unknown field (allDay) and Missing title are refused by the field itself, in Almanac’s own words, and Try is disabled with its reason. Broken JSON marks line 4. Empty asks for a call.
  • Format, Minify, Wrap and Copy sit above the field; Tab indents. The four choices in the dialog change the indent, when it is laid out, when it is checked and the line numbers, live.
  • Trying puts the busy card over the whole card; Almanac does not answer fills it with a plate and a normal Retry.

Press each sample: the status line under the field says valid, or what is wrong and where, in the same words Almanac answers with. Press Try on a valid one: the answer appears under the button and nothing else moves.

See where a call stops

A call goes through four steps: the call itself, the source’s profile, the event and the calendar. The step that refuses it is lit, the steps after it are not reached, and the rule that decided is a chip.

Expected:

  • Accepted: four checks and the summary says the call would be written. Unknown field, Missing title and End before start light Event (HTTP 422) with the rule as a chip; Unknown source lights Profile (404); Client token lights Call (403). Every refusal is the real check from request.rs or admin.rs.
  • Under the trace, the answer Almanac gives (status, message, remedy) and its JSON body. Copy on the trace copies the path as text for a bug report.
  • Running is the busy card over the placeholders, Empty says to pick a case, Failed has a Retry that runs the trace again.

Press each case: exactly one step is lit (or none), the ones after it are dimmed with Not reached, and the answer under the trace matches. The four choices change the trace live.

The event Almanac would write

The calendar event in plain words, a line-by-line comparison with the event already in the calendar (a new event or an update), and the curl command that repeats the call.

Expected:

  • New event (all options) is the Everything sample: every line of the comparison is added. Existing event, changed is the Home Assistant sample against the event already there: two lines are tinted, with + and - signs. Existing event, same says nothing would change. Refused shows Almanac’s 422 answer instead of an event.
  • Times read dd/mm/yyyy HH:MM in the event’s time zone (09:00 UTC is 11:00 in Brussels). Copy as curl is a bash block that copies as written, with $ALMANAC_URL and $ALMANAC_TOKEN left for you to set.
  • Sample data: the event already in the calendar is made up. Almanac’s dry-run does not look it up yet (see the README), so the update/create verdict and the comparison are what this page would show once it does.

Press each outcome: the badge, the spec, the comparison and the curl command change together, the card keeps a steady height, and the changed lines carry a sign as well as a tint.
