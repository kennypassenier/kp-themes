# Theme portraits — the pilot [scope-97]

**Decided (scope-98, scope-99): the three pilots were judged and the portraits stop there.**

**Scope (scope-99):** the portraits stop at these three pilots; no other theme gets one. Screenshots are taken for checking and not kept in the repository.

Kenny, 2026-09-15: can the essence of a theme — what makes it unique, its mannerisms, colours and motion — be shown on a page of its own, so a
new component finds its place in every theme more easily? This is the pilot: cyberpunk, formal and pastel.

## What is here

| File                                    | What                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `themes/<theme>/signature.json`         | the machine-readable essence; every entry cites the token, selector, keyframes or property proving it |
| `themes/signature.schema.json`          | its schema (JSON Schema 2020-12)                                                                      |
| `themes/verbs.json`                     | which verbs each package component performs (hover, press, enter, leave, load, attention)             |
| `research/theme-portraits/<theme>.html` | the page, generated by `npm run generate:portraits`; do not edit                                      |
| `portrait.js`, `portrait.css`           | the replay buttons and reduced-motion switch; the page's own layout (no `kp-` class)                  |
| `gates/advice-signature.mjs`            | `npm run advice`: component verbs a theme does not answer, never refusing                             |
| `tests/theme-portraits.spec.mjs`        | the pages in the browser; `gates/portraits.test.mjs` and `gates/advice-signature.test.mjs` in node    |

## The schema in brief

`idea` (at most three sentences) · `loadBearing` (claims) · `colourRoles` (role → token, use, never, live example) · `type` (role → face,
scale, case, tracking) · `shape` (radius, borders, shadows, signature) · `surfaces` (hero, app, footer: ground and ink) · `motion` (`flicker`
allowed or not, with its reason; six `verbs`, each with description, duration, easing, what reduced motion keeps, `open`, and a `demo`) ·
`ornaments` · `voice` (case, labels, icons, never) · `recipe` (situation → answer and existing components; `open: true` rows carry a
`proposal`) · `banner` (the worked example's markup). Every entry carries `proof`; an `open` verb or recipe row carries a `proposal`
instead, and is never presented as fact.

## How each section is shown

Each of the nine sections is a `.cat-block` with a Look-at text and a stage, so the judging panel, hash and prompt work per section. Motion is
shown as `catalogue/page-effects.html` shows reveals: live copies outside the stage, the verbs at rest inside it. Hover and press replay the
register's own `:hover` and `:active` rules (read from the loaded stylesheets, re-keyed on an attribute); the reduced-motion switch rewrites
the stylesheets' own `prefers-reduced-motion` guards, so what remains is what the stylesheets leave.

## What the pilot found

- **Attention is not answered in formal's or pastel's own manner.** Both alarms carry the theme's colours but move with the package's
  flicker, decode and jitter, which neither theme allows. Marked open, with the held designs as proposals. The replays show it as it ships.
- **No theme has an entrance or exit for a dialog, popover or toast.** Pastel's register declares a dialog transition with nothing to move
  from; the advice check counts it, which is the limit of reading selectors.
- **A stamp needed a dossier (fixed, scope-98).** The stamp was absolutely placed and only the emphasis card was positioned, so the pilot banners used none; it now floats at the top end of every labelled card.
- **The anatomy documents drift from the registers.** Listed in the agent report; the registers and tokens were taken as the truth here.

## Recommendation

Approve the shape on these three, then generate the other nineteen from signatures written the same way. Settle the open verbs per theme as
decisions, and rebuild the per-theme alarm (scope-96) from each theme's `attention` row and `flicker` flag.
