Almanac: the redesigned Calendars page

Almanac turns events from Home Assistant, the homelab, kyu and AI sessions into Google Calendar entries. This is its Calendars page rebuilt on kp-themes 11.0.0 in formal: the header and counts, the attention band, the calendars table with its typed delete, the new-calendar dialog, the profile files and the uses map (feat-ui-1). 7 sections, 7 pairs. The data is sample data apart from the version and the totals; each section says which parts are made up.

Calendars page: header and counts

The page says what it is in one sentence, offers one main action (New calendar) and keeps the rare one (Reload profiles from disk) in an overflow menu; three counts under it each lead to the rows they count.

Expected:

  • Header: the title Calendars, one sentence of what the page is for, the primary New calendar and a More menu holding Reload profiles from disk (with a line saying what it does). Nothing else competes with the primary button.
  • Counts: Calendars 3, Sources 4, Profile files not served 1, exact numbers, tiles of one height. Each count is a toggle that filters the rows it counts (press it: it reads Filtering × and the line under the strip says which rows are shown; press again to clear); the not-served tile is the only warning tone. The fourth tile is a trend: events delivered per hour over 24 hours as a sample sparkline (sample data); point at it to read one hour. Press Nothing yet and all three read 0 with no warning.
  • States: Loading keeps the three tiles with a waiting value; Failed is one plate over the strip’s whole footprint with a normal Retry (it reloads). Menu: Open shows the menu open at its button.
  • Phone (390): the actions move under the sentence, the tiles stack, nothing scrolls sideways and no label is cut.

One header row, the primary button in formal’s navy, the menu on an opaque plate at its button, three equal tiles with the number large and the words wrapping instead of cutting.

Attention band: what needs a person

Standing problems sit in one band under the counts, worst first, each with the action that fixes it; an action Almanac refuses answers with a toast and leaves the problem where it is.

Expected:

  • Both: Google Calendar cannot be reached (critical, destructive tone) first, then 1 profile file is not being served (warning). Each has one fix button at its end: Check again and Reload profiles from disk.
  • Press a fix button with Fix works chosen: the button shows busy, then a short Done, and the problem leaves the band (the Problems row follows). Each answer raises its own toast flavour: Fix works a success toast, Nothing changed an info toast, Partly done a warning toast (the problem stays), Fix is refused an error toast saying why and what to do. A refused Delete in the Calendars table raises the destructive flavour.
  • Google only / File only / None: the band holds one problem or nothing; with none, the band takes no space and the line under it moves up.

Formal’s alert plates: red for critical with its icon, amber for the warning; the button sits at the end of each plate and text keeps air from the plate’s edge. The toast is an opaque plate.

Calendars table

Every calendar the service account sees: its name, its id (one click copies it), the sources that write to it, and a delete that is only possible when nothing writes there.

Expected:

  • Filled: three rows. The id is a code cell with a Copy button. Used by shows one tag per source; point at (or Tab to) a tag and a card says its token state, when it was last used and how many events it posted. Delete stands in the last column on every row: enabled for almanac-test, disabled for the two in use, and pointing at a disabled one says Used by home-assistant….
  • Delete almanac-test: a dialog asks you to type the name, says what is lost (every event on it) and keeps Delete off until the name is exact. With Server refuses the row stays and a toast says why; with Server accepts the row leaves at once.
  • Sorting: a click on a header sorts, another header adds a key; the choice is remembered. Phone (390): the rows become cards, the Delete button keeps its place at the foot of each.
  • States fill the table’s whole footprint: Loading the theme’s busy card, Empty a plate with a drawing and New calendar, Failed a plate with a normal Try again.

A hairline table on formal’s white, the id in mono on a quiet ground, tags as hairline pills, the destructive button outlined in red. The states keep the loaded height.

Deleting a calendar: type its name

Deleting a calendar removes every event on it, so the dialog says that and asks for the calendar’s exact name; the server can still refuse, and then nothing changes.

Expected:

  • The dialog shows What you lose (every event on it with its count), the name to type in code, the rule (capitals count) and a status line that is always there, so nothing moves. Delete calendar is off until the name matches.
  • Typed: nothing typed leaves the status empty; Wrong name says it does not match (and still keeps Delete off); Right name shows a success badge and turns Delete on. A name with spaces and a middle dot (Almanac · Huishouden) must be typed exactly.
  • Delete calendar with Server accepts: busy, then the dialog says it is deleted. With Server refuses: a toast says a source started using the calendar a moment ago; the dialog stays so nothing is lost by accident.

Formal’s dialog plate with a hairline, the typed name in mono, a quiet rule line and a red Delete that is clearly off until the match; no text touches the plate edge.

New calendar dialog

Making a calendar is rare, so it lives in a dialog opened from the header: a name, a note on who it is shared with, and a refusal for a blank name.

Expected:

  • Open: a dialog with a title, one sentence, two sections (Name and Sharing), and the actions Cancel and Make and share. Closed shows the New calendar button, which opens the same dialog for real.
  • Blank name refused: pressing Make with an empty name does not go on; the field gets a red error, a summary names it and the focus lands on it. Filled has no error. Making it shows the busy button; Refused by Google answers with a toast and leaves the name typed.
  • Owner not set: Almanac cannot make calendars (nobody would see one); the form is off and the button says why when pointed at.

Formal’s dialog: hairline plate, section headings in small caps weight, the required mark beside the label, the error in red under the field; no text against the edge.

Profile files: not served and served
