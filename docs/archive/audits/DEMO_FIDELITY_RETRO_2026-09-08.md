## Unsure / not independently verified

- **B5 (focus-ring channel order)**: read from CSS only; not confirmed by rendering in a browser, so it is possible some other rule (not found in the files read) restores the demo's order. Flagged, not asserted as certain.
- **Item 6/7 (boot bar and wording)**: `js/effects.js`'s `arrival()` function is shared between retro's `boot` routine and a `card` routine (phantom/synthwave); it is possible a *different*, retro-specific boot path exists elsewhere that this read missed. A repo-wide grep for `kp-boot` and `ROUTINES.arrival` turned up only the one function, but the effects module is 826 lines and only the arrival/reveal sections were read closely.
- **Item 3 (ramp colour)**: contrast and hex values were computed independently (Python, WCAG 2.x relative-luminance formula) rather than taken from any committed report; `docs/RESEARCH_2026-09.md §21` was not opened to check whether it separately re-measured `--sidebar-accent` for this purpose.
- Whether `gates/check-layers.mjs` or `gates/check-tokens.mjs` would actually fail on any of the Class A items was not tested by running them (per the task's "keep it minimal" instruction); the "what goes red" column reports only what is visible from the test/gate source, not confirmed execution.
- The showcase/demo pages other than `examples/concept.html` (e.g. any standalone `retro.html` under `showcase/`) were not checked for a possibly closer reproduction of the window/spec-sheet/status-bar elements found missing above.
