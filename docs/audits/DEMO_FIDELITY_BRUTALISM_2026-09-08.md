## Class C — the package adds beyond the demo (for completeness, summarised)

The demo shows one narrow slice of the component library (nav + dropdown, hero, three button variants, a form, a dossier card, a toast, a footer, two marquees). The register answers "one answer per component root (56 of 64, the eight helpers excused)" (`anatomy.md:78`), so most of the register's ~1193 lines style components the demo never rendered at all:

- Full component set not in the demo: `.kp-icon-button`, `.kp-badge`/`.kp-tag`, `.kp-health`(`__dot`), `.kp-skeleton`, `.kp-progress`(`__value`), `.kp-spinner`, `.kp-empty`(`__title`), `.kp-error`, the text-shape classes (`.kp-id`, `.kp-url`, `.kp-numeric`, `.kp-timestamp`, `.kp-masked`, `.kp-copyable`(`__button`), `.kp-truncate`, `.kp-cell-break`, `.kp-cell-truncate`), `.kp-table`, `.kp-datatable`(`__bar`,`__sort`,`__status`,`__page`,`__search`), `.kp-diff`(`__line`), `.kp-timeline`(`__marker`,`__when`), `.kp-tree`, `.kp-reorder`, `.kp-tab`(s), `.kp-breadcrumb`, `.kp-pagination`, `.kp-wizard`(`__steps`), `.kp-datepicker`(`__day`,`__weekday`,`__title`,`__panel`), `.kp-colorpicker`(`__swatch`,`__value`), `.kp-shortcuts`(`__row`,`__group-label`), `.kp-palette`(`__input`,`__group-label`,`__status`), `.kp-combobox`(`__input`,`__list`,`__status`), `.kp-theme-menu`(`__status`), `.kp-dialog`(`__title`), `.kp-popover`, `.kp-menu`(`__item`), `.kp-tooltip`, `.kp-confirm`, `.kp-alert`(`__label`), `.kp-grid`(`__tile`), `.kp-split`(`__pane`,`__separator`), `.kp-fieldset`, `.kp-form__summary`.
- The generic hook-attribute vocabulary (`data-kp-surface`, `data-kp-hero-grid`, `data-kp-divider`, `data-kp-reveal`, `data-kp-reveal-trigger`, `data-kp-label`) that S45 requires every theme to answer — the demo uses ad hoc classes (`.hero`, `.marquee`, `.rule`, `.stamp`) instead.
- `.kp-menu` gets `padding: calc(2 * var(--kp-focus-ring-inner-width, 2px))` (register :602-604) so a menu item's own focus ring doesn't collide with the frame's ink line — a fix for a component the demo's dropdown didn't need (AR30's dashboard test, per the register's own comment).
- `scrollbar-color` declared for the theme (register :1006-1008) — the demo does not style scrollbars at all.
- Field selectors extended beyond the demo's single `.control` class to `.kp-datatable__search`, `.kp-combobox__input`, `.kp-palette__input`.

None of this is a fidelity problem — it is the register doing its actual job (S45's full hook vocabulary across 64 component roots) beyond what a single concept page could exercise.

## Uncertain / not fully verified

- **A6** (hsl vs oklch): confirmed empirically that `gates/check-layers.mjs`'s `leakedColours()` does not reject `oklch(from var(...) ...)` — both forms are exempted because they contain `var(`. The recorded reason in `anatomy.md` ("the layers gate reads hsl") does not hold up against the gate's actual logic as read and tested. There may be a different real reason (browser support for the wider `oklch()` gamut/chroma math, or a rendering difference under `calc(c + 0.1)` that has no HSL equivalent) that was not written down — this is worth asking Kenny to confirm with whoever wrote that anatomy line, or worth re-testing directly in a browser, which this audit did not do.
- **Copy/content text** (headline, lede, laurel captions, spec-sheet body, dossier paragraph, footer copy): not diffed word-for-word against the demo beyond the stamp (A9). KT5 requires all such text to live in `js/strings.js` rather than be hard-coded, so some rewording relative to the demo is expected and likely approved-by-policy rather than a fidelity slip — but a full copy diff was out of scope given the time budget and wasn't performed. If Kenny cares about exact wording parity, that needs a separate pass.
- **B6** (select chevron via `::picker-icon`): not verified in an actual browser render — `::picker-icon` is a newer CSS feature; whether it renders equivalently to the demo's manual gradient chevron across the project's tested browsers (Chromium/Firefox per the demo's own contrast note) was not checked.
- Did not run any Playwright/browser test, per instructions — all "what goes red" answers are read from test source, not from an actual run, so a test name listed as the likely red case is a reasoned inference, not a confirmed result.
