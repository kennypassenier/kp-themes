Step list

The steps of one run, live: an update, an import or a deploy as a list whose items are waiting, running, done, failed or skipped. `data-state` on each item is the source; js/steplist.js keeps the rest in step with it: the spinner on the running step, a hidden state word after each title, `aria-current="step"`, and a polite status region that announces a change.

When to use it

For a process with named stages that a person watches or comes back to. For one measured quantity use a progress bar; for a form split in pages use the wizard.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

This unit reads no data attributes of its own.

Accessibility

  • Built in — each step reads “title, state”, the running one carries `aria-current="step"`, and a change is announced once through a hidden status region (a burst in one tick is one announcement).
  • Built in — the list itself is not a live region, so it does not re-read every note on every change.
  • Yours — name the list, and give a failed step a note that says what to do.

Variants and states

NameWhat it is
data-state`pending`, `running`, `done`, `failed`, `skipped` or `current` (the step a journey stands at now: a ring with a dot, no spinner): the mark, the colour and the word follow it.
.kp-steplist--journeyThe steps side by side on one path, joined by a rule drawn in the step’s colour once reached; a column under 30rem of its own width.
data-kp-toneA step’s own colour, `1` to `5` (`--chart-N`), or any value with the page’s own step colour set on the item: the reached mark and the rule into it wear it.
.kp-steplist__timeHow long the step took, as the page prints it; in a journey, the date it was reached.
.kp-steplist__noteThe one-line description under the title.
buildSteplist(rows, { label })Builds the `ol` from rows `{ id, title, note, state, time }`; attach it afterwards. `data-kp-step-id` carries each id.
setStep(list, id, change)Changes one step (`state`, `title`, `note`, `time`) and says so once in the status region; the id is `data-kp-step-id` or the step’s index.
the markDrawn from `data-state`: the theme’s spinner while running, and a glyph for done, failed and skipped (the glyph tokens are in the knobs). It is never the only carrier: the state word is there too.
the words`stepPending`, `stepRunning`, `stepDone`, `stepFailed`, `stepSkipped` and the announcement `stepAnnounce(title, state)` are in the dictionary, so `setStrings()` translates them.
