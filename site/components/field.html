Form field

A label, a control, optional help text and an error, with the wiring between them: the label points at the control, the help and the error are announced with it, and an invalid field says what is wrong in words rather than by turning red.

When to use it

For a single control that stands on its own — a search box in a toolbar, one filter in a sidebar. Inside a form that validates, reach for the form field instead: it is the same shape connected to the form’s own state, and using this one there means writing the error handling twice.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

This unit reads no data attributes of its own.

Accessibility

  • Built in — the label is a real label, the help and the error are pointed at by the control, and the invalid state is announced rather than only painted.
  • Built in — the checkbox and the radio are drawn larger than the browser’s default, and their tick takes a colour the theme can correct; the label is clickable too, which is what actually makes the target big enough for WCAG 2.5.8.
  • Built in — a select’s open list is drawn by the package in the combobox’s look in every browser, Firefox included, while the native select stays the control a screen reader reads and a form submits. Write data-kp-select="native" (React: drawn={false}) on a select that should keep the browser’s own list; a multiple select always does.
  • Yours — give every control an id and point the label at it, or wrap the control in the label.
  • Yours — write the error as a sentence that says what to do. “Invalid” tells the reader only that you noticed.
  • Yours — keep the help text short: it is read out before the reader has typed anything.

Variants and states

NameWhat it is
.kp-fieldThe stacked default: label above control, help and error under it.
.kp-field--checkBox first, label beside it — the order it is read in and the order it is clicked in. Help and error move under both.

.kp-field__input--multilineA textarea: taller, and resizable vertically only, because one dragged wider breaks the column it sits in.
.kp-fieldsetA group of radios or checkboxes with a legend, so the question is read once before the answers rather than once per answer.
inline layoutA radio group laid out in a row instead of a column, with the legend on its own line above them.
.kp-field__requiredThe required marking: a star and the word, because a star alone is read as “star”.
