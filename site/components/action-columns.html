Buttons in shared columns

A list’s row buttons on columns the whole list shares: a button of one role starts at one edge and has one width on every row, whatever its label, and a row without that role leaves its column empty. In a list the browser does it — the list is a grid, each row a subgrid — and by position from the end no script is needed. A table measures, through `attachActionColumns()` in js/actions.js.

When to use it

For a list or a table whose rows carry the same few actions, so the eye finds Open in the same place on every row. Not for one row’s toolbar, and not for a long row of actions: four from the end is what the stylesheet places alone, and beyond that a menu reads better.

Accessibility

  • Built in — the buttons keep their order in the markup; the columns are layout only, so the tab order is the row’s own.
  • Built in — a column a row leaves empty holds nothing focusable.
  • Yours — name a button by what it does to that row (“Open INC-4471” for a screen reader) when the visible word alone is the same on every row.

Variants and states

NameWhat it is
.kp-action-listA list (`ul` or `ol`) whose rows are one grid: the row’s text first, then one column per button.
.kp-row-actionsThe button box in a row or a table cell. Empty, it takes no room.
data-kp-actionA button’s role, for rows whose buttons are not the same from the end: one column per role, in the order the rows give them.
.kp-action-list--leadRows with a lead column before their words, as wide as the widest lead and no wider; the buttons keep their shared columns. In a narrow list the lead stays beside the words and the buttons go under them.
.kp-action-list__lead, __mainThe lead (a state dot or badge, a file’s format, a day and hour) sits on the title’s first line; the words are the main part.
.kp-action-list__title, __text, __metaThe title in the heavier weight, one muted sentence, and a muted line of parts set apart by a dot that never starts a wrapped line.
.kp-action-list__whenA moment as two lines, a day over an hour; in a `next` row the second line takes the primary ink.
.kp-action-list__more, __payloadA fold for a payload (the accordion’s bare item), and the text inside it in the mono face at a readable height.
li.kp-action-list__groupA heading row across the whole list (Upcoming, Past); the keyboard walk skips it.
data-kp-state on a row`new` (unread), `active` (claimed, in flight), `warn`, `failed`, `next` (the next one up: the bar, a primary wash and the lead in the primary), `done` and `past` (quieter ink, not opacity). Every row reserves the bar, so a state moves nothing.
setRowBusy(row, busy, button)The row carries `aria-busy`, every button in it refuses a press with `aria-disabled` (the focus stays), and the pressed one shows the theme’s spinner in `.kp-button__busy` while its words (`.kp-button__text`) keep their room, so no column moves.
removeRow(row)The row leaves the theme’s way (at once under reduced motion). When the focus is in it, the focus goes first to the same place in the next row, else the row before, else the list.
data-kp-row-keys / attachRowKeys(root) / ROW_KEYSj or ↓ next row, k or ↑ the row before, Home and End the first and last, Enter on the row fires `kp-row-open` with `{ row }`. Never while typing in a field or with a modifier held; a button in a row keeps Enter. One row is in the tab order, so Tab reaches the list once.
on a phoneIn a list narrower than 30rem the buttons go under the row’s text, side by side, spread over the full width in equal columns, so a role still lines up from row to row. In a narrow table they stack in the cell at one width.
data-kp-action-measuringWhat the script writes on a table for the moment it measures, every button at its own size.
