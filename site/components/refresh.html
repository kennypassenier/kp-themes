Automatic refresh

The small control that refreshes a page by itself: “Every 30 s” or “Paused”, with “updated 12 s ago” beside it and a thin rule that runs down to the next refresh. The app does the fetching; the control fires an event on each tick and waits to be told whether it worked.

When to use it

A dashboard or a list that should stay current without a reload. For a single “updated” line alone use the freshness line; for a manual reload only, a plain button.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — it never eats typing: a refresh waits while a dialog is open, a form field has the focus or the tab is hidden, and runs once on return. A failed refresh keeps the data and says when it retries, with Retry now; R refreshes at once outside a field.
  • Yours — fetch on `kp-refresh` and always answer with `done`, or the control waits for ever.

Variants and states

NameWhat it is
the script`attachRefresh(root, { now })` wires every `[data-kp-refresh]` and returns a detach; `refreshOf(el)` answers the handle; `refreshDone(el, ok)` is `detail.done(ok)` by element; `setRefreshInterval(el, seconds)` changes the interval from the page (`by: 'script'` on the event). `REFRESH` is the selector, `REFRESH_DEFAULT` (30) and `REFRESH_CHOICES` the defaults behind the attributes; the events are `REFRESH_EVENT` and `REFRESH_INTERVAL_EVENT`.
kp-refresh detail`{ reason, interval, done(ok) }` with `reason` one of `timer`, `now` (the button or R), `retry` and `return` (the tab came back with a refresh due).
.kp-refresh__bar / __chooser / __menu / __segmentsThe first row: the chooser (the menu button of the `menu` look or the segmented control of the `segmented` look, which scrolls inside the card when it is wider than it) and, after it, the freshness line and Refresh now.
.kp-refresh__line / __ago / __busy / __now / __countThe freshness line “updated 12 s ago”, which gives way to “updating…” in the same width, the button that refreshes at once and the thin rule that runs down to the next refresh.
.kp-refresh__custom / __input / __apply / __problemThe “Other…” form: a number of seconds, Apply and the line that refuses what is not a whole number.
.kp-refresh__failure / __note / __retryThe warning after a failed refresh: “Last refresh failed, retrying in 30 s” and Retry now.
data-kp-refreshThe seconds the page opens with; 30 by default, 0 opens paused.
data-kp-refresh-choicesThe seconds offered, `0,15,30,60,300` by default (0 is paused). “Other…” takes any whole number of seconds.
data-kp-refresh-mode`event` (default: the app fetches), `page` (reload the page) or `region` (fetch the same URL and swap only the region).
data-kp-refresh-regionThe selector of the element swapped in `region` mode; focus and scroll stay.
data-kp-look`segmented` (default) or `menu`.
data-kp-rememberA name: the choice is kept per page and device.
data-kp-stale-afterSeconds after which the freshness line turns stale; three times the interval by default.
data-kp-refresh-hover`pause`: no refresh while the pointer is over a table being read.
