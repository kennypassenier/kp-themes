Problem alert

An alert with three fixed parts: what is wrong, why, and what to do now, with the fix beside them. It has the shape of an error and its remedy. A container updates its problems by key, so one that is still true is the same element, is not announced again and keeps the focus on its fix.

When to use it

Something is wrong and the person can fix it: a calendar that is not shared, a setting that is missing. For a passing message use the toast; for a plain note use the alert.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — an alert that is still true is not announced again, and the focus stays on its fix; a command has a Copy button that says it copied.
  • Yours — write the three parts as sentences a person can act on, and give each problem a stable key.

Variants and states

NameWhat it is
data-kp-problems-mode`each` (default: one alert per problem, the worst first), `list` (one alert holding every problem, the tone of the worst) or `fold`.
data-kp-problems-fold-fromWith `fold`: from this count (5 by default, at least 2) one alert holds the worst open and “Show the other N”. Change it at any time, like the mode.
data-kp-remedy-labelThe word before the remedy; “What now” by default.
data-kp-problem-layout`stacked` (default) or `inline`, which runs what, why and remedy into one paragraph.
per item`severity` (`critical`, `warning` default, `info`), `command` (set in code with a Copy button), `action`, `dismissible` (default off: a real problem is not closable until it is fixed).
