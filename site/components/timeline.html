Timeline

An ordered list of things that happened, each with its moment and a marker down the left. The rule between markers is drawn on the marker itself, so a one-item timeline has no line hanging under it.

When to use it

For a history in order — releases, an audit trail, the states an application passed through. Not for a schedule of what is still to come, where a list with dates reads better than a line. Not as a chart: this is prose in order, not a measurement of time.

Live example

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

This unit reads no data attributes of its own.

React usage

import { Timeline } from '@kp-soft/themes';

Declared in components/patterns.jsx; the package re-exports every component from its root.

Accessibility

  • Built in — the markers are decorative and the list is an ordered list, so the order is announced rather than drawn only.
  • Yours — use a time element with a machine-readable moment; the printed text is for the reader.
  • Yours — put the newest entry where your readers expect it, and say which end that is if the order could be either.

Variants and states

NameWhat it is
.kp-timeline__itemOne entry: a marker column and the text beside it.
.kp-timeline__markerThe dot, and the rule to the next entry — except on the last, which draws no line.
.kp-timeline__whenThe moment, quiet, above the text, in same-width digits so a column of times lines up.
