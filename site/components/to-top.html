Back to top

The control that appears once the reader is a way down the page and takes them back — the view and the focus both, which is the half usually left out.

When to use it

On a page long enough that getting back is work: an article, a log, a table of a few hundred rows. Not on a page that fits on a screen, where it is a button that does nothing. Not as a substitute for a navigation — going up is not the same as going somewhere.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — the focus goes back with the view, and it moves without scrolling, so the control cannot undo its own journey.
  • Built in — while it is not on the screen it is not in the tab order either.
  • Built in — the scroll follows the page’s own scroll-behaviour, so a reader who asked for less motion gets none.
  • Yours — give it a name. A button with only an arrow in it is announced as “button”.

Variants and states

NameWhat it is
data-kp-to-top-afterHow far down it appears, in pixels. Default 400.
data-kp-to-top-targetA selector for where the focus should land instead of the top of the document. The focus moves without scrolling either way, so naming a landmark cannot undo the journey.
data-kp-to-top-shownWritten by the module while the control is on the screen. Read it, do not set it.
kp-to-topThe event, on the control, whenever it appears or goes away: `{ shown }`.
--kp-to-top-offsetHow far it sits from the corner, both ways at once. Default 1.5rem.
