Status rows

One row per item that is read or checked one by one: a mark, the item’s name, a short detail and, when it failed, a Retry that tries that one item again. `data-state` is `ok`, `loading`, `failed` or `empty`; each is a shape and a word as well as a colour. js/statusrow.js (`buildStatusList`, `setStatus`, `attachStatusLists`) keeps the mark, the spoken state, `aria-busy`, the Retry and the announcement in step with it, and fires `kp-status-retry` when a Retry is pressed and `kp-status-change` when a row changes.

When to use it

For a page that reads many things separately (a backup per stack, a check per host) and must say which one is slow, which failed and why. For the steps of one run use the step list.

Accessibility

  • Built in — each row reads “name, state”, a loading row has `aria-busy`, and a change is announced once through a hidden status region; more than three changes in one tick become one summary.
  • Built in — the Retry is named after its row, and when the focused Retry goes away the focus moves to the row’s name.
  • Yours — name the list, and write a reason that says what to do.
