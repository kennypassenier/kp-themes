Typed confirmation

A destructive action that turns on only once the reader has typed its name. On a button that already asks for a confirmation, `data-kp-confirm-type="media"` makes the package’s confirmation dialog show what will be lost (`data-kp-confirm-loses`, the id of a template or an element), the field, the rule it is matched by and a line that says whether it matches; Confirm stays disabled until it does, carries the button’s own words (or `data-kp-confirm-label`), and Enter in the field confirms a match. Spaces at the start and the end never count; capitals count unless `data-kp-confirm-case="any"`. In a page’s own dialog or form, `data-kp-type-confirm="media"` with `data-kp-type-confirm-for="<button id>"` builds the same block and holds that button off.

When to use it

For the few actions that delete something that cannot come back and whose name the reader should look at first: wiping a stack, removing a service, deleting a backup set. For an everyday delete the plain confirmation or an undo is enough.

Accessibility

  • Built in — the field is labelled by the sentence with the name in it and described by the rule and the match line; the match line is a polite live region; the field has the focus when the dialog opens.
  • Built in — Confirm is disabled until the name matches, so neither a click nor Enter can act before; a match is a word on the success plate as well as a colour.
  • Yours — list what will be lost in plain words, keep the name the one the reader knows it by, and keep the action rare: a typed name asked every day is typed without reading.
