Operations page

The anatomy of a dashboard page in one fixed order whatever the source order: header, KPI strip, attention band, toolbar, card grid. Pure CSS. Empty parts take no room; the toolbar (or the header) stays reachable while the cards scroll.

When to use it

An operations or overview page that follows the principles of the house layout. For a free-form page use the page and stack layouts.

Live example

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

This unit reads no data attributes of its own.

Accessibility

  • Built in — the visual order is fixed but the source order is yours, so keep it the reading order; spans collapse to 6 and 12 columns on a tablet and one on a phone by the page’s own width.
  • Yours — give each card a title and keep the KPI strip to figures that matter.

Variants and states

NameWhat it is
the footprintThe page is a footprint host (js/footprint.js): while it is `loading` or `error` it keeps the height it had when it was ready, as a minimum, so the failed plate stands where the cards stood. `FOOTPRINT_MAX` is the cap behind the knob, 48rem; the other hosts are the matrix, the entity grid, the checklist, the notices, the gallery, the availability grid and the request inspector (`FOOTPRINT_HOSTS`).
.kp-ops__head / __kpis / __attention / __toolbar / __bodyThe five slots, in this fixed order whatever the source order. The head and the body are required; a missing or empty slot takes no room. The attention slot is a `.kp-attention` with one alert per problem; the toolbar is a `.kp-toolbar`.
data-kp-stateOn `.kp-ops`: `loading`, `empty` or `error` (the last is the failed page above). The page is a footprint host: in a state it holds the height it had when ready (js/footprint.js), so the page under it does not jump.
data-kp-ops-width`80vw` (default, never under 64rem), `full` or `measure` (64rem).
data-kp-ops-cardsThe default span of a card in twelve columns: `12`, `8`, `6` (default), `4` or `3`.
data-kp-ops-sticky`toolbar` (default), `head` or `none`: the part that stays reachable.
data-kp-ops-failed`plate` (default) or `keep`: what a page with `data-kp-state="error"` shows. `plate`: the alert takes the body, centred at heading size, at the height the page had, the stale cards hidden. `keep`: the cards stay, the alert is a band on top. Switchable at runtime.
data-kp-uniform`off`: cards in a row keep their own height; by default a row has one height.
data-kp-density`comfortable` (default) or `compact`.
data-kp-spanOn a card: `3`, `4`, `6`, `8` or `12` columns.
data-kp-ops-wide / data-kp-ops-narrowOn header actions: `wide` ones leave the header on a phone; `narrow` entries of its More menu appear there.
