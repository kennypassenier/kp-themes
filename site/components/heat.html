Heat grid

Rows by many columns of small cells, each toned by a state or a value: a stack per night, a service per hour. A label column on the start side (a press on a name toggles it, `data-kp-heat-toggle`), the column axis, an optional summary row whose cells fill from the bottom (`data-kp-share`), a legend (`.kp-heat__legend` with `.kp-heat__swatch` and `.kp-heat__ramp`), a picked column (`data-kp-picked`, `data-kp-heat-picked`) and hover detail through the hover card. A state is told by a pattern as well as a colour: a bad cell is striped, a warn cell ruled, a future cell dashed, a cell before the record hatched. `setHeat(el, spec)` in js/heat.js writes it and keeps its footprint in every state; `data-kp-heat-owned` leaves the picked column and the pressed names to the page. A cell on the axis that is not named is `data-kp-minor`; a cell that cannot be pressed is `data-kp-inert`.

When to use it

When a reader looks for the odd one out in a dense grid of states or values and then asks about one cell: coverage per night, uptime per hour, a count per day. Not for a few categories (use a table or a chart) and not for a month calendar (use the calendar, which has the weekdays).

Accessibility

  • Built in — a `grid` with row and column headers, one tab stop, arrow keys, Home and End, Ctrl with them for the corners; Page Up and Page Down send `kp-heat-page`, Enter and Space press a cell (`kp-heat-pick`), a pressed name sends `kp-heat-row`.
  • Built in — a state is a pattern as well as a colour; a column name that is not drawn stays in the tree.
  • Yours — give every cell words (`label`) that say what its colour says, and put the detail of a picked column in a polite live region.
