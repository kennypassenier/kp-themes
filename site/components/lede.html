Lede

The short paragraph under a heading that says what the section does. The markup works without the script; the script ties the lede to its heading for a screen reader, folds a long one behind “More”, adds a “Learn more” link and lists headings that have no lede.

When to use it

Under every card title and page section, in plain words. For a note about one field use the field’s help text; for a warning use the alert.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — the heading is described by its lede (`aria-describedby`), so it is read with the heading; a folded lede’s button says what it will do.
  • Yours — write the lede in the user’s words and keep it to one or two sentences.

Variants and states

NameWhat it is
data-kp-lede-measure`narrow` (48ch), `normal` (70ch, default) or `full`.
data-kp-lede-tone`muted` (default) or `plain`.
data-kp-lede-collapsibleA lede longer than about N characters (140 by default) shows its first sentences and folds the rest behind More and Less.
data-kp-lede-linkA URL: a “Learn more” link at the end.
data-kp-lede-requiredOn a container: every heading inside it must have a lede, and `missingLedes` lists the ones that do not. Card titles are always checked.
data-kp-blockingOn a `.kp-field__why` line: the reason stops the form, so it is written in the destructive ink instead of the quiet one.
collapsible with a linkA lede with `data-kp-lede-collapsible` and `data-kp-lede-link` folds, and Learn more stands at the end after the folded part.
switchable at runtimeSwitchable at runtime: changing `data-kp-lede-collapsible` or `data-kp-lede-link` redraws the lede.

Options written as attributes are read again when they change. A component of your own that reads options from attributes does the same with watchOptions(element, attributes, onChange) from js/live-options.js.
