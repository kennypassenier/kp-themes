Pagination

Numbered pages with previous and next, gaps where the range is cut, and the current page marked by weight as well as by the attribute that announces it.

When to use it

For a list a reader may want to come back to, where a page number is a place they can return to and link to. Not for a feed, where endless scrolling suits the reading; and not inside the data table, which builds its own pager.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

This unit reads no data attributes of its own.

React usage

import { Pagination } from '@kp-soft/themes';

Declared in components/overlays.jsx; the package re-exports every component from its root.

Accessibility

  • Built in — the gap is hidden from a screen reader and the current page is announced rather than only drawn.
  • Built in — a link that would point outside the range is not rendered, so nobody tabs onto a page that does not exist.
  • Yours — name the nav element, and give each number a label if the number alone is not clear (“page 3”).
  • Yours — use real links with real URLs. A page number that only works with script cannot be shared.
  • Yours — say how many pages there are; a reader cannot guess from a cut range.

Variants and states
