Connection banner

The banner that says the connection is gone: “No connection, 3 changes waiting”, “Reconnecting…”, or “Refused” when the browser is online and the server is not. It sits directly under the navigation bar, pushes the content down instead of covering it, and takes no room at all while the connection is fine.

When to use it

A page that keeps working offline or on a stream: a PWA, a dashboard on a live feed. For data that is merely old, use the freshness line; for one failed action, use the toast or the problem alert.

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — each change is announced once; going offline is assertive, the rest polite. On a phone the banner is one line plus Retry now.
  • Yours — report failed fetches and dropped streams with `setConnection`, answer `kp-connection-retry` with a real try, and pass the number of changes that are waiting.

Variants and states

NameWhat it is
the script`attachConnection(root)` wires every `[data-kp-connection]` and returns a detach; `connectionOf(el)` answers the handle; `setConnection(el, state, { pending, why, attempt })` reports a state. `CONNECTION` is the selector and `CONNECTION_STATES` the five states; the events are `CONNECTION_STATE_EVENT` (`{ state, previous, pending }`) and `CONNECTION_RETRY_EVENT` (`{ attempt, auto }`).
.kp-connection__bandThe plate inside the banner: a `.kp-alert` (warning offline, destructive refused, success when it is back) with `__mark`, `__body` (`__title`, `__why`, `__meta`: the time to the next try) and `__retry`, the Retry now button.
onlineNothing is drawn and no room is taken.
offlineThe warning plate: what, why, what now, the time to the next try and Retry now.
reconnectingA try is under way, with its attempt number.
backSuccess: “Connected again” stays for a moment, then leaves.
refusedThe destructive plate: the browser is online and the server refuses; the app’s own sentence is the reason.
data-kp-connection-source`browser`, `app` or `both` (default): which reports count.
data-kp-connection-graceMilliseconds (3000): a drop shorter than this shows nothing.
data-kp-pendingThe number of changes waiting, exact; also `setConnection(el, state, { pending })`.
data-kp-placement`bottom` (default, fixed to the foot of the window) or `top` (in the flow, under the navigation bar). Change it at any time.
data-kp-back-msMilliseconds (3000) “Connected again” stays.
data-kp-retry`off` leaves the Retry now button out.
data-kp-retry-delaysSeconds between automatic tries, `3,10,30,60` by default (the last repeats); `off` for none.
data-kp-announce`state` (default) says each change once, politely and going offline assertively; `off`.
