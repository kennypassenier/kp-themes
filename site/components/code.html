Code block

A payload, a request or a snippet: a head with its title, what it is and its tools (Pretty and Raw for JSON, Wrap, Copy), and the text in the mono face. js/code.js (`setCode`, `prettyJson`, `attachCodes`) fills every `[data-kp-code]`; loading lays the busy card, empty, binary and failed say so at the body’s height.

When to use it

A message body, an HTTP request, a command to copy. For a running log use the log; for a change use the diff.

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

Accessibility

  • Built in — the body is a named region that takes focus, so a keyboard can scroll it; a copy is announced.
  • Built in — line numbers are never copied or read.
  • Built in — a long line scrolls inside the plate’s padding, and the scroller that takes focus is the `code` element, so a keyboard can reach the end of a line.

Variants and states

NameWhat it is
.kp-code--cellThe block as a table cell: no title, wrapped words, three lines shown. Copy copies the whole value, folded or not; `data-kp-copy="false"` takes it away. An empty payload is the muted line “empty payload”; a loading one is a skeleton line, because the table around it lays the busy card.
data-kp-code-open`inline` (default: “Show all 40 lines” opens the rest in the cell) or `dialog`.
data-kp-binary-size / data-kp-downloadThe size in bytes of a payload that is not text, and the link to fetch it: the cell shows “binary, 2.1 kB” and the link, never the bytes.
data-kp-truncated`shown/total` in bytes, “1024/4096”: the foot line says only the start was sent.
data-kp-code-wrap / -max / -layoutWrapped from the start; folded past N lines; Raw instead of Pretty.
state`loading`, `empty`, `binary` (with `size`) and `error`.
truncated`{ shown, total }`: the foot says only the start was sent.
data-kp-code-title, -language, -size and -linesThe head’s title, the language it names (`JSON` offers Pretty and Raw when the text parses), the size it states, and line numbers in a gutter outside the text, which a copy or a selection never takes.
setCode options`setCode(el, { text, title, language, size, lines, wrap, maxLines, layout, copy, truncated, state, message, loadingWords })`: `maxLines` folds past that many lines (0 never), `layout` is `pretty` or `raw`, `copy: false` leaves Copy out, and a page that draws later calls it again to redraw in place.
.kp-code--cell and its attributesThe table-cell block: `data-kp-code-open` (`inline` or `dialog`), `data-kp-code-language="auto"`, `data-kp-binary-size`, `data-kp-download`, `data-kp-truncated` (`shown/total` in bytes) and `data-kp-copy="false"`. Loading is a skeleton line, since the table around it lays the busy card.
kp-code-copy, -copy-failed, -wrap, -layout and -fold`{ text }` (the whole value, folded or not), nothing, `{ wrap }`, `{ layout }` and `{ folded }`.
prettyJson and CODE_COPIED_MS`prettyJson(text)` is the JSON laid out with two-space indents, or `null` when it does not parse; `CODE_COPIED_MS` is how long “Copied” stays, 1500 ms.
codeLabel … codeCopiedAnnouncement stringsEvery word of the block is in the dictionary: `codeLabel`, `codeWrap`, `codePretty`, `codeRaw`, `codeFormat`, `codeShowAll`, `codeShowLess`, `codeLines`, `codeEmpty`, `codeBinary`, `codeTruncated`, `codeLoading`, `codeError` and `codeCopiedAnnouncement`.
TOML and shell colouringA block whose language is `toml`, `bash`, `sh`, `shell` or `zsh` colours its parts: sections (`.kp-code__section`), strings, values (numbers and booleans), comments and, in a shell, variables (`__var`). The colour is a word-shape as well as a hue (bold section names, italic comments), so it reads without it.
data-kp-code-highlight`off` turns the colouring off for a block that should read as plain text.

Options written as attributes are read again when they change. A component of your own that reads options from attributes does the same with watchOptions(element, attributes, onChange) from js/live-options.js.
