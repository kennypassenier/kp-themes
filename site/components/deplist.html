Dependency list

A short list of rows “paperless → postgres” that says what needs what, numbered in the order things must go. Every row is the same columns, each name carries its identity mark, a cycle is one red row, and the list folds past eight rows with an exact “Show all 23”.

When to use it

Before a change: who notices if this app stops or updates. Not for a picture of the whole network (a graph) and not for progress (a step list).

Framework-free markup

Server-rendered markup with the behaviour attached by js/auto.js, the one module that does anything on import. The snippets above are that markup, printed from the same string the example renders.

These are the framework-free channel's props. A selector is how a module finds an element, a read is a value you set on it, and a written one is state the module puts back for the stylesheet and for you to read.

Accessibility

  • Built in — an ordered list; each row reads as one sentence (“paperless needs postgres”), the arrow is hidden from a screen reader; the heading is a polite live region with the exact count.
  • Yours — pass real data (`from`, `to`) and a heading that says what the rows are.

Variants and states

NameWhat it is
the script`attachDeplists(root)` wires every `[data-kp-deplist]` and returns a detach; `setDeplist(el, items)` hands over the rows (`{ from, to, state }`); `deplist(el)` answers the handle; `orderDependencies(items, { numbers })` and `depText(items)` are the ordering and the copy text on their own. `DEPLIST` is the selector, `DEPLIST_COLLAPSE` (8) the default behind `data-kp-dep-collapse`, and `DEPLIST_RETRY_EVENT` is `kp-deplist-retry`.
data-kp-dep-direction / -arrow / -link / -self / -empty / -heading / -copy / -rowsWhose sentence it is (`from-needs-to` default, or `from-reaches-to`); the arrow glyph; a template for each name’s page (`{name}`); whether a thing lists itself (`hide` default or `show`); the sentence of an empty list; the heading with the exact count (`{n}`); a button that copies the rows as text; and the least rows the list stands as high as in a state (3).
.kp-deplist__heading / __body / __list / __row / __groupThe heading (a polite live region with the exact count), the body, the ordered list, one row and a group heading.
.kp-deplist__no / __name / __name--to / __text / __arrow / __stateThe cells of a row, the same columns in every row: the number, the thing that needs, the thing needed (`__name--to`), the words of the row for a screen reader, the arrow and the state (a `.kp-badge`).
.kp-deplist__cycle / __foot / __more / __copy / __bone / __busyThe destructive row of a cycle (a `.kp-alert--destructive`), the foot with “Show all 23” (`__more`) and the copy button, the placeholder rows and the busy card of a loading list.
data-kp-dep-order`numbers` (default: one row per step, numbered 1, 2, 3) or `none` (the order given).
data-kp-dep-group`by-to` or `by-from` with `data-kp-dep-order="none"`: rows grouped under the app that changes.
data-kp-dep-statesA word and a tone beside each needed thing: running, stopped or unknown.
data-kp-dep-collapseHow many rows show before “Show all N”; 8 by default.
data-kp-state`loading` (the busy card over placeholder rows), `empty` and `error` (the package’s plates with Retry), each as high as the list was.
state badgesThe state badges are one column of one width, with a least width for the narrow layout.

Options written as attributes are read again when they change. A component of your own that reads options from attributes does the same with watchOptions(element, attributes, onChange) from js/live-options.js.
