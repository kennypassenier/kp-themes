Combobox

.kp-combobox: a text input that filters a list, driven by js/combobox.js, and the same thing as a tag input. Anything that opens is shown open on this page as well as live: the open copies are frozen in the exact markup the module writes, so they can be compared across themes without chasing a list that closes when you look away.

Closed

Look at: closed, a combobox is a text input with a label, and it must sit in a form beside a .kp-field__input without looking like a different control — compare the two. It is not the same rule in the stylesheet (the combobox takes the card's ground, the field takes the page's), so a theme whose card and page differ will show two different boxes side by side. That difference is a finding, not a matter of taste. The status line under it is empty until you type.

Open, with the list showing

Look at: the list floats over what follows it, on a surface of its own with a boundary that stays visible against whatever is behind — here the list covers the note under the box, and the note must not show through. The highlighted option (Cold store, moved to with the arrow keys) must be told apart from the others by more than a hair of tint: in a theme with a loud register, check that the highlight is still readable and that the text on it keeps its contrast. The list is as wide as the input, no wider. It hangs from the bottom of the whole .kp-combobox, so when the status line sits inside the box the list opens under the status line, a line away from the input it belongs to — look at that gap and decide whether it reads as one control.

Filtered to nothing

Look at: when nothing matches, the module closes the list rather than showing an empty one, and the status line under the input says No results. So the whole message is that one small line: it must be legible in every theme, and it must be close enough to the input to read as its answer. There is no "nothing found" row inside the list and no way to offer "add this" — if a theme needs one, that is a request for the package, not something this page can show. Type zzz into the live box beside the frozen one: both must look the same.

Forty options

Look at: the list stops at its maximum height and scrolls inside itself; the page must not grow to fit it. The scrollbar, where the platform draws one, must sit inside the list's boundary and not hide the right edge of the options. Scroll the list to the end and keep scrolling: the page behind it should not start to move, or should move only once the list is exhausted. Tag input

Look at: data-kp-tags turns the combobox into a tag input. The tags already chosen sit above the input as .kp-tag pills; each has a remove button that must be hittable, must turn to the alarm colour on hover, and must be named "Remove …" to a screen reader. Choose an option: it becomes a tag, disappears from the list, and the list stays open for the next one. With the input empty, Backspace removes the last tag. The tag row must wrap rather than scroll when it fills.

Keyboard

Look at: Tab into the box and never touch the mouse. Focus opens the list. Down and Up move the highlight while the caret stays in the input — typing must keep working at every moment. Home and End jump to the ends; Down on the last option stays on the last (this box does not loop). Enter takes the highlighted option and closes the list; with nothing highlighted, Enter does nothing here and would submit a form around it. Escape closes without choosing. Tab leaves and closes. The highlight you see must always be the option Enter would take — if hover and the arrows disagree, that is the fault.
