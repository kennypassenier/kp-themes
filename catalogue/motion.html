Motion

How things move in every theme [scope-142]: a dialog leaves the way it came, a box eases to its new size when what is in it changes, what arrives in a box arrives the theme's way, and what leaves plays the theme's own exit while its space closes. All of it is js/motion.js, which js/auto.js loads by itself; every speed comes from the theme's own dialog entrance, and a reader who asked for reduced motion gets none of it. The buttons in each block play it; the markup in each stage is what you write.

Dialog closing

Look at: open the dialog and close it with either button or Escape. It must leave the way it came, the theme's own entrance played backwards, in about two thirds of its time, and the page behind it must not jump when it is gone. Nothing to write for it: every .kp-dialog on a page that loads js/auto.js closes this way.

A box that grows and shrinks

Look at: add and remove readings. The card must glide to its new height both ways, never snap and never overshoot, with the theme's own character while it moves (formal rules its frame in, terminal moves a line at a time, and so on); everything under the card moves with it. Opt a box in with data-kp-size-motion; dialogs, accordions, tabs, tables, toasts and the other components do it without.

What leaves

Look at: remove one message or row with its ✕: it must play this theme's own exit (formal folds it up like a letter, retro shrinks it in pixel steps, titanium runs it through the colours titanium takes under heat, high-contrast lays REMOVED across it, one per theme), its space must close during the exit, and nothing may be drawn over the element above or below it. Then Remove all at once: they go one by one, the lowest first, each starting when the one before is halfway. Bring them back lets them arrive again.

// One element: the theme's exit, then it is removed.
await leave(row);

// Hidden instead of removed.
await leave(panel, { hide: true });

// Several in the same task: one by one, the lowest first.
for (const row of selected) leave(row);

Leaving: the options

Look at: the same rows with the defaults changed by a custom property on the box. On the left --kp-leave-stagger: 1: Remove all waits for each exit in full before the next. In the middle --kp-leave-fold: after: each exit plays out before its space closes. On the right --kp-leave-fold: ghost: the space closes at once under a copy that plays the exit. Each must still end with every row gone and the card at its smallest.

Custom property Default What it does
--kp-leave-stagger 0.5 How far into one exit the next of several starts; 1 waits for each in full.
--kp-leave-fold together When the space closes: together a third into the exit, after once it is over, ghost at once under a copy that plays the exit.
--kp-leave-pause 0 With after: milliseconds of empty space before it closes.
--kp-motion-scale 1 On the root: plays every dialog close and resize slower (above 1) or faster (below 1).
--kp-close-max / --kp-size-max 600ms / 480ms The longest a dialog close and a resize may take, whatever the theme's entrance.
data-kp-arrive="none" off On a box: what arrives in it simply appears (a live view's redraws).

From a script

Look at: nothing moves here; it is the code for a page that does not load js/auto.js, or that drives the motion itself. 
import { attachMotion, closeDialog, easeSize, leave, themeMotion, withoutOvershoot } from '@kp-soft/themes/js/motion';

attachMotion(document);                 // every dialog and component box on the page, and [data-kp-size-motion]
const stop = easeSize(card);            // one box by hand; stop() undoes it
await closeDialog(dialog, 'saved');     // close with the theme's motion; resolves when it is shut
await leave(row);                       // the theme's exit, then removed
const { open, close, size, ease } = themeMotion(); // the theme's timings, in ms
el.animate(frames, { easing: withoutOvershoot(ease) }); // the theme's curve without its overshoot
