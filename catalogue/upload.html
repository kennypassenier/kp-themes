Upload

.kp-upload: a drop zone that is a label for a real file input, and a list of rows the consumer drives with setProgress, setDone and setError from js/upload.js. The package paints the states; it never sends a file. The rows below are the exact markup the module writes, frozen at a chosen moment of an upload.

  • Empty
  • Dragging
  • A file list
  • Errors
  • In a narrow pane

Empty

Look at: the zone is a dashed frame on a muted ground with its words centred; it must read as a place to drop something, not as a disabled box. It is a label for a hidden file input, so Tab must land on it — the focus ring has to show on the zone, and in a theme where it shows nowhere, a keyboard user cannot see where they are. Press Enter or Space: the browser's file dialog opens. Choose a file larger than 5 MB and it must appear as a refused row with the reason.

    Dragging

    Look at: while a file is held over the zone the module sets data-kp-dragging: the frame takes the primary colour and the words the full ink. The difference from the empty zone above must be obvious at arm's length — a person dragging a file is looking at the file, not at the zone. The frozen copy is on the left; drag a real file from your desktop over the live zone on the right and the two must match from the moment the file enters the zone until it leaves or drops — the zone accepts the drag at its first event, and passing over the words inside it must not switch the state off. Nothing may change size when the state flips, or the target jumps away from the pointer.

    Live

      A file list

      Look at: four rows in four moments: waiting (no progress yet), uploading at 64 %, done with a message, and a file whose name is 90 characters with no space in it. In every row the name, the size and the remove button must sit on one line, with the thin progress bar under them and the message under that. The size must stay right-aligned in tabular figures. The long name must break or ellipse inside its row — it must never push the size and the remove button out of the row or make the page scroll sideways. Each remove button must be named after its file.

      Errors

      Look at: a refused file stays in the list with its reason on its own row — too large, wrong type, one too many — rather than a single message about "some files". The row's border and its message take the alarm colour, and the message must pass contrast on the ground; the file name stays in the ordinary ink so it can still be read. An error row must be told from a done row without colour: the words are what say it. The failed upload in the last row was accepted and then broke half-way; its bar stays where it stopped.

      In a narrow pane

      Look at: drag the pane as narrow as it goes. The zone's words must wrap inside the dashed frame. In the rows, the 90-character name is the first thing to give: it must wrap or ellipse while the size and the remove button stay whole and visible. A remove button pushed out of reach at 320 px is a file nobody can take back. Nothing may overflow the dashed edge of the pane.
