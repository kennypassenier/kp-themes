Page parts

The parts that belong to the page rather than to its content: the footer .kp-footer, the side note .kp-side-note, the command palette .kp-palette, and the theme menu with its groups, options and swatches (.kp-theme-menu, .kp-theme-group, .kp-theme-option, .kp-swatch). The palette and the theme menu are shown open; the theme menu in this page's own bar is the live one.

Footer

Look at: the footer is the quietest thing on a page: a rule above it, muted ink, a smaller size, and generous padding that grows with the window rather than jumping. The first is one line. The second holds three columns of links laid out with the layout layer's .kp-autogrid: the links must inherit the footer's quiet voice while still being recognisably links, and the headings must not shout louder than the page's own. Narrow the window: the columns must stack, never squeeze into a word per line.

Side note

Look at: the side note is the smallest, most muted text the package draws — a file code or a caption at the edge of a section, hidden from screen readers because it repeats nothing they need. It must still be legible: check its contrast with the Devtools colour tool in the palest and the darkest theme. A register may turn it into a stamp or a vertical label; the long note in the narrow pane must then still wrap or stay inside the pane, never overlap the heading beside it.

Command palette

Look at: the frozen palette is on the card surface with a strong boundary; its input has no box of its own, only a rule under it, and the list below scrolls inside the palette. Group labels are small capitals in the muted ink. The first command is the highlighted one (is-active, the keyboard's position): a soft wash of the ink across the whole row, not the accent colour. Descriptions are smaller and muted, and key hints sit at the row's end without competing with the label. The status line under the list says how many commands match. Press Open the commands (data-kp-palette-open, so it opens through the palette's own open and fires kp-palette-open), or Ctrl+K: the live palette opens modal near the top of the window with focus in the input; type "lock" and the list must filter to Lock out a line and the status must say "1 command". The match is literal by default: "read" must show only Readings for line 2, not also Report an incident, and "lk" finds nothing (a palette that wants letters in order says data-kp-match="subsequence"). Escape closes it and clears the query.

Palette with no match

Look at: a query nothing matches, frozen as js/palette.js leaves it: every command hidden, every group hidden with them, and the status line saying "No commands". The palette must not collapse into a line with no sign of a list — the input and the status keep their places, and the status must read as a message rather than as an empty footer.

Theme menu

Look at: the menu as themeMenuMarkup() writes it, shown open under its icon button: a popover with every theme in two groups, Light and Dark, each with a small muted label and a rule between the groups that runs the menu's full width. Each option starts with its swatch — a circle split between that theme's own ground and primary colour, with a boundary so a pale swatch on a pale menu is still a circle — and the theme on screen carries a check at the row's end and a heavier weight. The menu is taller than most windows, so the list scrolls inside the popover; the scrollbar must stay inside the rounded corners, never run square across them. It is attached: choosing a theme here changes the whole page, exactly as the bar's menu does.

Theme menu, React shape

Look at: the same menu as components/theme-switcher.jsx renders it, frozen open with Terminal chosen: the list is a .kp-theme-menu__list under the button at its end edge, each option has its label in .kp-theme-option__label and the chosen one a drawn check (.kp-theme-option__check) instead of the text glyph. Put it beside the block above: the two channels must be indistinguishable apart from that check. This copy is not attached — its check stays on Terminal whatever the page wears, because only React moves it.

Theme picker as buttons

Look at: the picker without a menu: the same grouped options laid out as rows of small bordered buttons on the card surface, each with its swatch before the name. The theme on screen is marked twice, by a border in the selected colour and by a check after its name. Hover a button: a wash of the ink, not a colour. The groups wrap as rows with their labels above them and a rule between. Press any button to switch the page's theme. The picker is a list here because the grouped options are list items; the package takes the browser's list indent and markers away, so the first row starts at the list's own edge.
