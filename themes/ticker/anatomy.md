# ticker — anatomy

> How this theme answers the questions in
> [DESIGN_INVARIANTS.md](../../docs/DESIGN_INVARIANTS.md). Ticker is the
> sixth theme lifted in 5.0.0 (S48, LIFT_PLAN row 6). The concept demo
> Kenny approved on 2026-09-08, "Open Outcry"
> (scratchpad/ticker-demo.html), is the reference for every value below.

## The idea

The trading screen — tabular figures, a running band, green and red that
mean something, density as a virtue. Amber fields on black, numerals that
line up every time, panel titles in reverse video. The temptation this
theme invites is a flashing cell when a value changes, and it is refused:
"cuts, not dissolves" is the demo's own thesis (Curio's Bloomberg
Terminal style guide, quoted in the demo's header note) — every one-time
reveal swaps state with no transition property at all, gated by an
IntersectionObserver so it fires once, the instant the element scrolls
into view. This is the theme a table wants: JobTracker's pipeline, a
ledger, a log.

## What is load-bearing

1. **Amber acts, yellow labels.** `--primary` is amber, `--accent` the
   paler label yellow; every other colour on the page is a grey, and the
   reverse-video treatment (amber field, black ink) is reserved for the
   controls that act — the primary button, the nav's call to action, the
   dossier's panel header — never for a whole surface.
2. **No motion at all.** `--fx-duration: 0ms` already makes every hover,
   focus and state transition in the whole base layer instantaneous for
   this theme, without a line of register code (`css/_rules.css` and
   `css/components.css` read the token generically). The register itself
   declares no `transition` or `animation` property anywhere: every
   reveal is a bare class swap the browser resolves in one frame, which
   is what "cuts, not dissolves" means mechanically, not just visually.
3. **Tabular numerals, mono display.**
   `font-variant-numeric: tabular-nums` on every identifier, timestamp, spec value and field —
   the theme's whole thesis is that a column of figures never reflows —
   and headings are the mono face in capitals.
4. **Radius 0, hairlines at 100%.** A rounded corner or a soft divider
   would say "dashboard product"; this says "screen." Every divider is
   one flat pixel, dim, no blur, no torn edge — a printed rule, this
   theme's own refusal of the round's razor tear.

## The register (5.0.0)

`css/ticker-register.css` is the theme's answer to the hook vocabulary
(S45):

- **Surface.** The hero grid stacks the laurels, the microlabel, the
  headline and the platforms line against the spec sheet, generated by
  `css/themes.css` from the `surface-hero-*` tokens (AR38); the
  `[data-kp-surface] h1` rule the register adds is plain — the display
  size, no shadow, no bar — because ticker's answer to "what marks a
  heading as this theme's own" is restraint itself.
- **Emphasis.** A `<mark>` at rest is underlined in the boundary tone,
  muted ink; armed and pending it goes quiet until the reveal lands, then
  the amber wash and the amber underline arrive together, in one frame. A
  dossier's redactions are hidden by colour only (background the
  foreground token, ink transparent), never `display:none` — a screen
  reader hears the sentence throughout (KT5) — and clear to the amber
  highlight on the trigger, in one frame, no wipe.
- **Reveal.** The headline reuses academia's `draw` routine (LIFT_PLAN
  row 10, X2 below): the same `IntersectionObserver` `rule()` already
  runs, generalised to h1, flips `is-in` the instant the element scrolls
  into view. Academia paints that flip as a drawn rule; ticker paints it
  as an opacity cut instead — one JS mechanism, two visual answers. The
  rule hook uses the same generic `rule()` mechanism it always does.
- **Divider.** One flat hairline pixel in a dim amber tone; the second
  divider is the quieter boundary tone. No blur, no torn edge.
- **Accent.** Deliberately nothing beyond the display-size heading rule
  every surface owes (see Surface above) — the restraint is the accent.
- **Arrival.** None. Printed matter — a trading terminal at the desk — is
  simply there; the demo builds no boot overlay and `--kp-arrival` is
  left unset.

Every hover is an instant colour swap (no transition property anywhere in
the register); every button is a hairline plate, the mirror modifier a
second frame at half opacity rather than a shadow (this theme has no
shadow anywhere — a shadow implies a light source, and the amber here is
a field colour, not one); every popover is the void with one hairline
frame, flat rows, no motion.

## X2 — the effects module

No change needed. The demo's headline wants exactly what academia's
`draw` routine already performs: the text untouched, no glyphs, no split
into words, `is-in` added the instant the element scrolls into view — the
same `IntersectionObserver` `rule()` runs, generalised to h1 (see
`js/effects.js`, the `routine === 'draw'` branch). Ticker's register
reads that class to paint an opacity cut where academia paints a drawn
rule; the mechanism is identical, only the paint differs, which is the
whole point of the hook vocabulary being separate from its visual answer.
An earlier draft of this lift added a bespoke `cut` routine before
noticing `draw` already did the job — recorded here so the next lift
checks the existing routines first, as the brief already asks.

## X3 — fonts

None needed. `fonts/families.json` already ships `KP Ticker Sans` /
`KP Ticker Mono` (IBM Plex Sans / IBM Plex Mono, renamed under the OFL's
Reserved Font Name rule, R6-Q1) with `"themes": ["ticker"]`, and
`css/fonts.css` already carries the `@font-face` rules — this predates
the lift. The demo's own `<style>` block loads the two families
unmodified from Google Fonts under their original names for the demo
page alone (its own header note explains why: nothing in a demo file is
a Modified Version of the font, so the Reserved Name restriction does not
apply to it). `themes/ticker/tokens.json`'s `theme-font-display` and
`theme-font-mono` already name `'KP Ticker Mono'` first, `theme-font-body`
already names `'KP Ticker Sans'` first — no token change was needed.

## Answers to the invariant questions

**DI1 — boundaries at 3:1.** `--border-strong` at 52% grey on the 4%
ground, the card and the popover, all already token-only — measured in
`gates/check-invariants.mjs`, no change needed for this lift.

**DI2 — the focus ring.** The demo's own stacked order, composed as a
broad `:focus-visible` override: amber (`--ring`), then the near-white
foreground, each separated from the element and from each other by a
background-coloured gap —
`0 0 0 2px var(--background), 0 0 0 4px var(--ring), 0 0 0 6px var(--background), 0 0 0 8px var(--foreground)`.
Reads the same over the amber primary button as over the void, because
neither channel is the surface it sits on.

**DI3 — states you can see.** Derived by lightness; amber at 55% has room
both ways, unchanged from the token contract.

**DI4 — colour is never the only carrier.** Unchanged from the token
contract measured at L3: offer (green plate) and rejected (red plate)
10.6 apart under deuteranopia, above the floor of 12 is not claimed here
— this is the existing token measurement, not a register concern, since
the register introduces no new status colour.

**DI5 — the flash threshold.** Nothing in the register interpolates at
all: no `@keyframes`, no `transition` property, no `animation` property.
Every reveal is a bare class swap the browser resolves in the same
frame it is requested, which is DI5's ceiling met by having nothing to
rate — `reports/di5.md` carries no ticker row because
`gates/check-motion.mjs` found nothing to scan in this stylesheet.

**DI6 — light or dark.** `color-scheme: dark`; ground 4%, card 8%,
popover 12% — unchanged from the token contract.

**DI7 — reduced motion.** Trivially honoured: there is nothing to
reduce. Under `prefers-reduced-motion: reduce` every reveal resolves to
its rest state exactly as it would in `no-preference` (see the "no
transition property" point above) — the register does not even need a
`@media (prefers-reduced-motion: no-preference)` block, since it
declares no motion for that block to guard.

**DI9 — theme colour stays in the token layer.** Every value in
`css/ticker-register.css` is `var(--token)`, a relative colour of one
(`hsl(from var(--primary) h s l / 0.18)` for the mark's wash, and
similarly for the two dividers), or a bare literal with no colour
component (`1px`, `0.35`, `0.02em`). No texture is declared
(`--fx-texture` is left unset) — the demo names none, and a data-dense
screen earns its density from the numerals, not a pattern.

## What the demo showed and the package now renders exactly (S49)

Built exactly, with two exceptions, both because the package's shared
machinery has no place for them without a change wider than one theme's
lift — reported here rather than built quietly, per S49:

1. **The market tape does not run on the generated concept page.** The
   demo's header note calls it "a bonus element, not in
   `showcase/concept-demo.json`'s 30" — added because the round's own
   brief asked for "a marquee that pauses until visible and under
   reduced motion," with no inventory slot naming one. The generated
   page (`showcase/examples.mjs`'s `conceptBody()`) is one function
   shared by every theme with an approved demo; adding a ticker-only
   section to it is a shared-infrastructure change outside one lift's
   ownership (`gates/integrate-lift.mjs` draws that same line: a lift
   owns its register, its spec, its anatomy and its tokens, not the
   generator). The register carries no tape CSS either, for the same
   reason a consumer would have nothing to point it at — it is not built,
   not merely hidden.
2. **Off-screen pause is not built even as a general mechanism.**
   Independent of point 1: no register in the package pauses a
   continuously-looping animation until it scrolls into view — brutalism's
   marquee, the package's one precedent for a seamless `-50%` loop, runs
   continuously behind its `prefers-reduced-motion` guard with no
   `IntersectionObserver` gating at all. Building that mechanism from
   scratch for a bonus element not in the required inventory was judged
   out of proportion for this lift; it would need its own `TIMINGS` row,
   its own `js/effects.js` hook and a decision about whether every
   existing marquee-style loop in the package should gain the same
   behaviour, which is a question for Kenny, not a single lift.

Everything else — the reveal mechanism, the focus ring, the buttons, the
fields, the dossier, the dividers, the dropdown, the whole approved
inventory — is built exactly as the demo shows it, token for token.

## What this theme may not do

- **No shadow, anywhere.** A shadow implies a light source; the amber
  here is a field colour on the void, not a source. The mirror modifier
  is a second hairline frame, never a drop shadow.
- **No easing, no draw.** A reveal is a cut: every state change in the
  register happens with no `transition` property declared at all. A
  future addition that reaches for `ease` or a duration is not this
  theme.
- **No flash on update.** The temptation of a trading screen is a cell
  that flashes when its value changes; DI5 counts it and this theme
  refuses it categorically, not just in the demo's own three examples.
- **No third hue outside the token contract's status colours.** Red and
  green exist only where `--destructive`/`--success` and the status
  tokens already put them.
